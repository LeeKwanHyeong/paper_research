# Hard-LMM 단계별 예측 정보 접근성 진단

**완료 / 로컬 — 주요 이력 요약은 최종 표현에서도 복원됐지만, 공통 성능 병목의 위치는 식별하지 못했다.**

Instacart에서 과거 평균 수량·최근 편차·경과시간 요약은 encoder의 마지막 상태와 memory 결합 뒤에도 읽을 수 있었다. 이 요약을 보조 예측기에 직접 제공해도 상수 잔차 보정보다 오차가 줄지 않았다. 따라서 이번 결과는 “유용한 정보가 특정 층에서 사라졌다”는 근거가 되지 않는다. 그렇다고 현재 입력으로 더 개선할 수 없거나 backbone이 최적이라는 뜻도 아니다. 확인한 것은 아래의 12개 요약과 두 고정 보조 예측기의 범위다.

사전에 정한 네 비교 중 Taxi 원본의 **최종 표현에 남은 잔차 신호**만 개별 기준을 통과했다. Taxi separate-key와 Instacart 두 모델에서는 통과하지 않아 공통 backbone 변경 근거로 채택하지 않았다. 기존 elapsed-age 후보의 실패 판정과 separate-key 기준선은 유지한다.

## 무엇을 비교했는가

대상은 `paper_research/master`의 기준 commit `e8fdd11`과 기존 original/separate-key seed42 checkpoint다. 계약과 추출·분석 소스를 고정한 뒤 CPU에서 실행했다. 계약 hash와 실제 실행한 소스·입력·checkpoint·출력 hash는 [execution_manifest.json](execution_manifest.json)에 있다. 완료 시각은 **2026-09-05 15:23:39 KST**다.

| 항목 | Taxi | Instacart |
| --- | ---: | ---: |
| 재사용한 train target 수 | 8,192 | 8,192 |
| 고유 train series 수 | 131 | 7,848 |
| 분할별 target 수 | 4,761 / 3,431 | 4,008 / 4,184 |
| body 경계: 수량 ≤ 기존 train p95 | 1,562 | 25 |
| tail 경계: 수량 > 기존 train p99 | 3,449 | 35 |
| body / tail target 수 | 7,782 / 82 | 7,811 / 73 |

두 모델은 각 데이터셋에서 정확히 같은 target·이력·series 분할을 썼다. Backbone은 이미 전체 train으로 학습되고 validation으로 선택된 checkpoint이므로, 보조 예측기의 series 분리만으로 새로운 일반화 평가가 되지는 않는다. 특히 Taxi의 모든 train series는 이전 진단에도 사용됐다. 이번 작업은 **회고적 train 내부 진단**이다. Held-out test를 읽거나 새 backbone을 학습하지 않았으며 5090을 사용하지 않았다.

실제 관측 경로는 다음과 같다. 각 encoder 위치의 마지막 관측 사건과 관측 사건 평균을 별도로 추출했다. `layer2_last`와 `h`는 동일한 tensor 값이며 별도의 정보 소실 단계가 아니다.

```mermaid
flowchart LR
    A[관측 사건 입력] --> B[Encoder 1층]
    B --> C[Encoder 2층]
    C --> H[마지막 관측 상태 h]
    H --> R[top-4 검색 결과 r]
    H --> F[실제 결합 h+r]
    R --> F
    F --> Q[기존 수량 head]
```

보조 예측기는 반대 series 분할만으로 적합했다. 예측 대상은 `log1p(다음 수량) − 기존 모델의 log 수량 예측`이다. 선형 ridge와 고정 tanh 128개를 더한 ridge를 사용하고, 반대 분할의 평균 잔차 및 같은 차원의 무작위 입력을 대조군으로 뒀다. 보조 예측기의 개선율을 backbone의 성능 개선율로 해석하지 않는다.

## 어디까지 정보가 읽히는가

아래는 Instacart separate-key에서 이력 요약을 복원한 선형 보조 예측기의 OOF R²다. 1에 가까울수록 해당 요약을 잘 복원한다. 평균·마지막·편차는 log 수량 기준이고, 마지막 상태와 사건 평균은 관측 범위와 집계 방식이 다르다.

| 복원한 이력 정보 | 1층 마지막 상태 | 2층 사건 평균 | 최종 상태 h | 결합 h+r |
| --- | ---: | ---: | ---: | ---: |
| 과거 평균 수량 | 0.9844 | 1.0000 | 0.9899 | 0.9890 |
| 마지막 수량 | 0.9999 | 0.8460 | 0.9997 | 0.9996 |
| 마지막 수량 − 과거 평균 | 0.9623 | 0.4698 | 0.9745 | 0.9715 |
| 사건 순서에 대한 수량 기울기 | 0.5633 | 0.9206 | 0.7197 | 0.6972 |
| 내부 총경과시간의 log 요약 | 0.9919 | 0.9948 | 0.9909 | 0.9896 |
| 시간배치 차이 J | 0.6569 | 0.6969 | 0.6754 | 0.6664 |

평균 수량과 최근 편차가 encoder를 통과하면서 전반적으로 사라지는 양상은 이 측정에서 보이지 않았다. 수량 기울기는 2층 사건 평균에서 마지막 상태보다 잘 읽히지만, 그 사실만으로 pooling 변경이 수량 예측에 도움이 된다고 판단할 수는 없다. 아래의 잔차 설명 검사가 그 추가 조건이다. 전체 12개 요약·10개 위치·4개 조합의 결과는 [feature_reconstruction.csv](feature_reconstruction.csv)에 있다.

Memory `r` 단독에서는 복원이 약하거나 불안정했다. 예를 들어 Instacart separate-key의 평균 수량 R²는 0.6395이고 일부 특성은 음수다. 그러나 실제 최종 표현에는 `h`도 더해진다. `r` 단독의 약한 복원을 전체 경로에서의 정보 소실로 해석하지 않았다. 음수 R²는 여기의 적합된 보조 예측기가 반대 분할 평균보다 못했다는 뜻이다.

## 그 정보가 기존 오차를 줄이는가

아래 수치는 각 비교의 **log 잔차 MSE 개선율(%)**이며, `선형 / tanh128` 순서다. 양수는 개선, 음수는 악화다. 실제 판정에는 표의 기본 대조군뿐 아니라 같은 차원의 무작위 입력 대조군, 양 분할의 개선 방향, series bootstrap 안정성, body MAE 방향도 사용했다.

| 비교 | Taxi 원본 | Taxi separate-key | Instacart 원본 | Instacart separate-key |
| --- | ---: | ---: | ---: | ---: |
| 이력 요약 F 단독 vs 상수 보정 | +7.387 / +7.624 | +1.147 / −2.185 | −0.171 / −2.891 | −0.191 / −2.893 |
| h에 F 추가 vs h | +3.974 / +2.709 | −0.692 / −0.429 | +0.053 / −0.087 | −0.181 / −0.258 |
| h+r에 F 추가 vs h+r | +3.978 / +2.588 | −0.656 / −0.402 | −0.005 / +0.264 | −0.234 / −0.739 |
| [h,r] 분리 입력 vs h+r | −0.829 / −2.775 | +0.522 / +1.239 | −1.048 / −2.944 | −0.409 / −0.612 |
| h+r 잔차 보정 vs 상수 보정 | +5.928 / +8.430 | +1.066 / −2.273 | −1.726 / −4.690 | −1.040 / −4.228 |

**Instacart에서는 F를 직접 주어도 상수 보정을 이기지 못했다.** 따라서 그 요약이 중간 표현에서 덜 복원되는 구간을 찾아도, 수량 예측에 필요한 정보가 그곳에서 사라졌다고 연결할 수 없다. 원본과 separate-key 모두에서 입력 위치의 보조 예측기, encoder의 각 위치, 최종 결합의 보조 예측기도 두 decoder 모두 상수 잔차 보정보다 pooled MSE가 높았다. 이 결과는 사용한 입력 요약·보조 예측기 범위에 한정된다.

**Taxi 원본에는 최종 표현으로 설명할 수 있는 추가 잔차 신호가 있었다.** 상수 보정 대비 MSE가 5.928% / 8.430% 줄고, 두 분할·무작위 대조군·보수적 bootstrap 하위 분위수·body 방향 조건을 모두 통과했다. 보조 보정 후 body MAE는 상수 보정 24.851898에서 23.652741 / 21.631246이었다. 이 효과만으로 head·학습 목적함수·checkpoint 선택 중 무엇이 원인인지는 분리하지 못한다.

**Taxi separate-key의 추가 개선 근거는 확보되지 않았다.** 최종 표현의 선형 보조 보정은 MSE가 1.066% 줄었지만 분할 방향과 body MAE 조건을 통과하지 못했고, tanh128에서는 2.273% 악화됐다. 이력 추가와 분리 결합도 전체 판정 기준을 충족하지 않았다. Taxi 원본에서 확인한 효과가 현재 separate-key 위에 추가로 남아 있다고 주장하지 않는다.

## 사전 기준에 따른 최종 판정

각 비교는 두 보조 예측기 모두에서 두 대조군 대비 MSE 1% 이상 개선, 양 분할 개선, 10,000회 paired series bootstrap의 하위 `.05/32` 분위수에서 개선량 양수, log MSE와 body MAE 방향의 비충돌을 요구했다. 이력 추가 비교에는 F 자체의 유용성도 요구했다. Bootstrap은 고정된 OOF 오차의 조건부 안정성 검사이며 정식 유의성 검정이 아니다.

| 사전 비교 | Taxi 원본 | Taxi separate-key | Instacart 원본 | Instacart separate-key | 공통 근거 |
| --- | --- | --- | --- | --- | --- |
| 최종 encoder 상태에 이력 요약 추가 | 불충족 | 불충족 | 불충족 | 불충족 | 없음 |
| 결합 상태에 이력 요약 추가 | 불충족 | 불충족 | 불충족 | 불충족 | 없음 |
| 덧셈 대신 두 상태를 분리해 읽기 | 불충족 | 불충족 | 불충족 | 불충족 | 없음 |
| 최종 표현에 남은 잔차 신호 읽기 | 통과 | 불충족 | 불충족 | 불충족 | 없음 |

Taxi 원본의 이력 추가 비교는 개선율 자체는 양수였으나 tanh128의 보수적 bootstrap 하위 분위수가 음수여서 통과시키지 않았다. 전체 세부 조건은 [contrast_checks.csv](contrast_checks.csv), 최종 판정은 [evidence_decision.json](evidence_decision.json)에 있다. 결과를 본 뒤 기준을 완화하거나 데이터셋별 다른 승자를 묶지 않았다.

## 검증과 증적

- **49개 테스트 통과**: target·padding 차단, 공식 출력 일치, hook 정리, 짧은 이력, finite 계산, series 분리, 반대 분할 통계, synthetic 정보 추가·제거와 판정 조건을 확인했다. [pytest.log](pytest.log), [pytest.xml](pytest.xml).
- 실제 4개 checkpoint의 중간 표현을 추출한 뒤 state hash가 유지됐다. 각 8,192개 target의 `h`·수량·이력 길이·logit·예측이 이전 진단 cache와 정확히 일치했다. 첫 배치에서 모델 공식 출력과도 대조했다.
- 추출 전 고정한 계약·소스·입력 hash를 분석 완료까지 확인했다. [추출 기록](extraction.log), [분석 기록](analysis.log), [실행 계약](execution_contract.json).
- 독립 감사에서 새 production 분석 helper를 import하지 않고 저장된 cache와 OOF 결과를 검산했다. **205개 hash, 85,821개 검사**, 잔차 MSE·원수량 지표·복원 R²·fit 통계·10,000회 bootstrap 재계산 최대 차이는 0이었다. [independent_audit.json](independent_audit.json).
- Raw body MAE·RMSE·tail MAE는 [decoder_metrics.csv](decoder_metrics.csv)에 별도로 보존했다. 원수량 지표에만 보정 log 수량을 0~20으로 제한했고 해당 건수를 pack별로 기록했다. 주요 잔차 MSE에는 이 제한을 적용하지 않았다. Time NLL과 e300 성능 채택 기준은 이번 진단의 평가 항목이 아니다.

원수량 지표의 현재 표본 기준선은 다음과 같다. 이전 전체 validation/e300 지표와 표본이 다르므로 직접 혼용하지 않는다.

상세 분석은 [analysis.json](analysis.json), 표 내보내기는 [build_summary_tables.py](build_summary_tables.py), 이력 단독 검사는 [history_usefulness.csv](history_usefulness.csv)다. 대용량 cache와 OOF 배열은 git에서 제외한 로컬 `search_artifacts/hard_lmm_information_access_20260905/`에 보관하며 manifest의 hash로 식별한다. 단위·계약 소스는 이번 독립 커밋에 포함하고 기존 미추적 `scripts/`는 포함하지 않는다.

독립 감사는 저장 OOF를 검산했으며 decoder를 다시 적합하거나 원본 parquet에서 이력을 재추출하지는 않았다. 그 부분은 계약 테스트·실행 parity·hash로 확인한 범위다. 재현은 `paper/scripts/run_hard_lmm_information_diagnostic.py --phase extract` 다음 `--phase analyze` 순서이며, 기존 증적 덮어쓰기를 막기 때문에 새 실행에는 별도 출력 경로와 실행 계약이 필요하다.

## 남은 작업 순서

**다음 작업 / 로컬 — 원시 관측 이력 전체에 추가 예측 신호가 있는지 확인할 비교를 설계한다.**

- 이번 F12 요약에 포함되지 않은 사건 간 상호작용·전체 순서가 separate-key의 수량 오차를 설명할 수 있는지 검토한다. 기존 h/r readout 실험과 구분되는 대상은 원시 관측 이력 전체다.
- 실제 추가 진단 전에 비교 모델의 용량, 수량 목적함수, series 분할, 상수·무작위 대조군 및 판정 기준을 고정한다. 보조모델이 약해서 신호를 못 읽는 경우와 입력에 추가 신호가 확인되지 않는 경우를 구분할 수 있어야 한다.
- 완료 조건은 “원시 입력에서 확인한 예측 신호가 encoder 이후에도 접근 가능한지 비교할 수 있는가”다. 이 단계가 설계되지 않으면 복원 R²가 낮은 위치만 근거로 encoder·pooling·memory 결합을 바꾸지 않는다.

**후속 조건 / 로컬 및 필요 시 5090 — 추가 신호와 위치가 확인될 때만 단일 변경 후보를 정한다.**

- 현재 새 backbone 구현이나 5090 실행 대상은 확정되지 않았다. 비교 설계 결과에 따라 필요한 실행 범위와 계약을 구체화한다. 이번 진단의 완료를 성능 개선 후보의 승인으로 해석하지 않는다.

방법의 범위와 사전 기준은 [진단 계약](../../contracts/hard_lmm_information_access_v1.md)에 정리했다. 문헌상 출발점은 [중간층 probe](https://arxiv.org/abs/1610.01644)와 [probe의 control task](https://aclanthology.org/D19-1275/)이며, 여기의 회귀·무작위 입력 대조군은 해당 논문의 분류 실험을 그대로 재현한 것은 아니다.

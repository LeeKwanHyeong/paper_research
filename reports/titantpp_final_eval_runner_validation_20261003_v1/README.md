# 독립 평가 준비: 원본 연결과 공통 실행기 검증

2026-10-03 사용자 승인 범위인 **평가 자료 적격성 조사·비교군 원본 연결, 이후 공통 실행기 검증**을 수행했다. 검증 데이터는 synthetic 및 CPU validation 표본으로 제한했다. held-out/test 예측·성능을 생성하거나 열지 않았으며, 새 학습·원격 실행·임대·실험 모니터 변경은 하지 않았다. 현재 열려 있는 `main.tex`도 변경하지 않았다.

### 이전 상태 보고 정정

앞선 10/3 설계 문서는 오래된 로컬 경로를 참조해 비교군 36개 원본이 없고 실행기가 미검증이라고 기록했다. 그러나 **10/1에 이미 원본 회수와 84조건 CPU 표본 검증이 완료**되어 있었다. 이번에는 해당 증적을 재사용하고, 실제 원본 경로를 새 registry에 연결했다. 이전 연구 산출물을 지우거나 새로운 날짜의 통과 기록으로 바꾸지 않았다.

10/1에 기록된 Intermittent의 **사업장 단위 재표집을 주 분석**, 개별 시계열 단위를 민감도 분석으로 사용하는 보완도 `effective_protocol.json`에 복원했다. 모델·선택 epoch·주요 지표·고정 비교 대상·seed는 변경하지 않았다.

기존 verifier를 현재 작업 상태에서 재실행했을 때 과학·산출물 확인 30개는 통과했고, 과거 작업 트리/추적 상태를 요구하는 2개는 달랐다. 그 재실행 결과는 `historical_verifier_rerun.json`에 별도 보존했다. 기존 `verification.json`은 실행 전 원문으로 복구했으며, `preserved_inputs.json`의 원래 SHA로 확인한다. 이를 과거 검증의 새 통과로 해석하지 않는다.

## 원본 연결 증적

`../titantpp_final_eval_checkpoint_binding_20261003_v1/evaluation_registry.json`을 실행기의 단일 checkpoint/source 입력으로 사용한다. 12개 동결 소스 묶음은 별도 프로세스로 가져오며 현재 작업 트리의 모델 코드로 대체하지 않는다.

- 로컬에 보존된 두 archive의 **755개 파일 SHA**를 재확인했다. 원격 재회수는 필요하지 않았다.
- 오래된 경로의 36개 selected weight는 원래 동결 소스로 CPU strict-load, tensor SHA, 최초 최소 validation raw 수량 RMSE의 선택 epoch를 다시 확인했다.
- 나머지 72개는 기존 CPU 감사와 현재 파일 SHA 확인을 재사용했다.
- 이 감사는 selected weight의 연결 검증이며 새로운 optimizer/last-state 감사나 전체 endpoint 재평가를 뜻하지 않는다.

원본 연결 보고서: `../titantpp_final_eval_checkpoint_binding_20261003_v1/report.md`.

## 공통 실행기 검증 범위

`evaluate_validation.py`는 새 구조 대조 세 소스 묶음의 24조건만 추론한다. 데이터마다 정렬된 앞의 두 validation 개체에서 최대 8개 target을 사용한다. 기존 84조건 예측은 10/1 증적의 checkpoint·tensor·선택 epoch·계약·source SHA와 현재 registry가 같음을 확인한 후 재사용했다.

표본은 Taxi 8개, Intermittent 8개, Instacart 2개, RAF 4개로 **공통 target 22개**다. target마다 학습 모델 9개 × 3seed와 단순 기준선 2개를 연결하여 **638행**을 검증했다. 데이터별 target 수가 작은 이유는 제한된 표본 규칙과 원래 loader의 적격 window 때문이며, 성능을 보고 표본을 고르거나 결과가 나쁜 target을 제외하지 않았다.

검사 내용은 다음과 같다.

- 모든 모델·seed의 target ID, 원수량, 관측 간격, 이력 길이 및 평가 split 일치.
- target 수량 변경 시 수량 예측·시간 loss 불변, target 간격 변경 시 수량 예측 불변, 단일/배치 결과 일치, 파라미터 불변, 유한 출력. 시간 loss 자체는 관측 target 간격에 의존하므로 간격 변경에 대한 불변을 주장하지 않는다.
- prepared 데이터 SHA와 `[entity, seq, recorded date]`를 포함한 target ID. 이것은 **prepared 행 식별**이며 원천 raw 이벤트의 중복 없음이나 출처 적격성을 증명하지 않는다.
- 직전/평균 수량 기준선은 같은 허용 이력에서 target과 padding을 제외해 계산. `seed=null`, 시간 NLL·seed 표준편차는 `null`로 기록한다. paired 차이 계산에 같은 기준선 벡터를 재사용해도 독립적인 seed 반복으로 세지 않는다.
- 고정된 세 학습 seed에 같은 재표집 draw를 적용하고, event 가중 합으로 seed별 지표를 만든 뒤 seed 평균을 계산한다. seed 재표집이나 예측 ensemble은 하지 않는다.
- Taxi는 공유 달력 시간 블록, Intermittent는 사업장 cluster, Instacart/RAF는 개체 cluster를 사용한다. 표본/블록이 부족하거나 draw가 유효하지 않으면 구간을 확정하지 않는다.

`validation_smoke/attempt1/statistics.json`은 계산 경로를 확인한 **validation 표본 산출물**이다. 논문용 성능이나 신뢰구간으로 사용할 수 없다. 전체 데이터 처리량·메모리·재시작 동작과 실제 최종 평가 환경은 아직 검증하지 않았다.

현재 runtime은 Python 3.12.10 / PyTorch 2.14.0 / NumPy 2.3.1 / Polars 1.31.0의 로컬 CPU이며, 상세 기록은 `runtime.json`에 있다.

## 평가 자료의 현재 적격성

별도 조사 결과는 `../titantpp_final_eval_population_eligibility_20261003_v1/README.md`와 `eligibility.json`에 기록한다.

- **Taxi:** 기존 자료는 2015년 1월의 GPS 0.02° 격자/시간별 집계다. 호환 GPS 열이 있는 공식 2015년 자료에서 2월을 구체적 후보로 찾았다. 사용자는 2월 자료의 과거 사용 여부에 **“확인이 필요함”**이라고 답했다. 미사용으로 간주하지 않는다. 1월에 선정한 격자 ID를 고정하고, 2월 활동량으로 개체를 다시 고르지 않는 규칙이 필요하다. 2월 28일은 168시간 블록 약 4개에 불과하므로 독립성이 확인돼도 현재 규칙에서 불확실성 구간은 탐색적으로 해석해야 한다.
- **Intermittent:** 사업장/시계열 구조는 확인했으나 원자료 출처와 과거 데이터의 식별 연결이 미확정이다. prepared 날짜 metadata가 2018~2030에 걸치므로 날짜가 실제 관측일인지 이동·생성된 날짜인지 확인해야 한다. 날짜만으로 미접근 미래 관측을 확보했다고 볼 수 없다.
- **Instacart:** 같은 2017 공개 자료의 mirror·파생본은 새 독립 표본이 아니다. 별도 자료와 사용 범위를 확인해야 한다.
- **RAF:** 기존 파일에 2002년 12월 이후 자료가 없으며, 원자료 사용 권한과 실제 미접근 기간/개체의 증거가 남아 있다.

이 판단은 독립적인 확증 가능성에 대한 것이다. 기존 자료를 명확히 **과거 자료 재평가**로 표시하는 경로는 별도로 설계할 수 있지만, 미접근 독립 평가로 바꿔 부를 수는 없다.

## 남은 작업 순서

**1. 독립 평가에 쓸 자료와 접근 이력을 확정한다 — 다음 작업 / 일부 외부 정보 대기**
- 대상: 우선 Taxi 2015년 2월 후보. 로컬 접근 흔적, 연구자 사용 이력, 원자료 출처/중복 및 시점 이전의 개체 선정 규칙을 확인한다.
- 다른 세 데이터는 원자료 제공자·추출/생성 이력·식별자 대응·자료 사용 범위가 필요하다. 네 데이터 모두 새 자료가 있는 것으로 전제하지 않는다.
- 완료 조건: 데이터별로 독립 평가, 명시적인 과거 자료 재평가, 또는 자료 미확보를 확정하고 raw/개체/event/target manifest를 고정한다.

**2. 확정한 모집단을 처리하는 실행 환경을 검증한다 — 다음 작업 / 1번 이후**
- 이번에 검증한 frozen 모델 adapter·단순 기준선·통계 계산을 재사용한다.
- 실제 전체 모집단 처리 wrapper, streaming/메모리/실패 보존, 지정 runtime과 자원 한도를 synthetic 또는 허용 validation 데이터로 확인한다.
- 완료 조건: 실행 대상·output·자원·마감·코드 SHA가 연결되고 표본 검증 밖의 운영 검사가 통과한 상태다.

**3. 동결된 최종 평가를 한 번 실행하고 원고에 연결한다 — 별도 실행 단계**
- 자료·환경이 구체화된 뒤 해당 모집단의 예측/성능 접근 범위를 확정해 실행한다. 현재 승인은 준비와 validation 검증에 적용됐다.
- 모든 비교 결과와 실패를 함께 보존하고, 새 평가가 뒷받침하는 주장만 현재 LNCS 원고에 추가한다.

**상태: 현재 과학 계약과 기존 구현 사실에 근거한 구조 설명.** 새로운 명칭은 미정입니다. 명칭 변경으로 구현의 기원이나 독창성 검증을 대신하지 않습니다.

# 전체 흐름

공통 이벤트 입력 → 첫 causal encoder block → 선택적 공유 이력 보정 → 두 번째 causal encoder block → 선택적 정적 prototype 조회 → 공통 수량·시간 head의 구조로 설명합니다. 공통 encoder는 hidden64·4head·persistent memory16을 유지합니다.

# 공유 이력 보정

- 첫 block을 지난 현재 hidden64와 직전 **관측** hidden64를 함께 사용합니다. 전체 backbone이 사건 두 개만 관측한다는 뜻은 아닙니다.
- bias 없는 128→15 공유 입력 projection과 exact GELU를 15→64 출력분기8개가 재사용합니다. 출력 projection은0으로 초기화합니다.
- 관측 prefix 수가 1·2·4·8·16·32·64·128보다 클 때 해당 분기를 사용할 수 있습니다. 모든 분기는 같은 현재·직전 관계를 쓰므로 ‘8개 서로 다른 lag 조회’라고 설명하지 않습니다.
- 활성 출력을 합한 뒤 항상8로 나누어 첫 block 출력에 더합니다. padding을 관측으로 세지 않고 withheld 경계를 반영합니다.
- 이 보정기의 파라미터는9,600개입니다. 공유 기저의 차원15나 분기8의 최적성은 현재 A–D 실험의 검증 대상과 구분합니다.

# 정적 prototype 조회

64개의 학습된 prototype에서 top4를 조회해 평균하는 후단 모듈이며 파라미터는4,096개입니다. 평가 중 가중치를 새로 학습하는 온라인 메모리 업데이트가 아닙니다. surprise·momentum·forgetting을 새로운 메모리 원리로 제안했다고 설명하지 않습니다.

# 구조 사실과 연구 주장의 경계

이 페이지는 구현 설명이며 문헌상 최초성을 확정한 문서가 아닙니다. 두 요소를 분리한 A–D 결과가 나오기 전에는 ‘두 요소가 각각 필수’ 또는 ‘새 메모리 알고리즘’이라고 주장하지 않습니다. 단순 잔차 MLP와의 비교가 필요한지는 A–D 결과 후 판단하며 현재 승인된 학습 범위에 자동 추가하지 않습니다.

# CNN·GRU 구현 범위

이 문서는 2026-10-04 승인된 구현의 동작을 설명합니다. 학습된 성능 결과나
원격 GPU 적격성 확인을 의미하지 않습니다. 실험 설계 원본은
`reports/titantpp_cnn_gru_width16_design_20261004_v1/design.json`입니다.

| 실행 경로 | Encoder 1 | 블록 사이 보정 | 보정과 CNN 파라미터 | 전체 파라미터, 최대 길이 256 / 84 |
| --- | --- | --- | ---: | ---: |
| `titantpp_history_mlp_width16` | 기존 Attention | 기존 8분기 MLP16 | 24,576 | 114,435 / 103,427 |
| `titantpp_cnn_mlp16` | 사건 Q/K/V CNN + 기존 Attention | 기존 8분기 MLP16 | 25,152 | 115,011 / 104,003 |
| `titantpp_gru54` | 기존 Attention | GRU54 잔차 보정 | 24,732 | 114,591 / 103,583 |
| `titantpp_cnn_gru54` | 사건 Q/K/V CNN + 기존 Attention | GRU54 잔차 보정 | 25,308 | 115,167 / 104,159 |

숫자는 모델을 실제 생성해 확인하는 계약 테스트의 예상값입니다. 최대 길이별
차이는 기존 학습 가능한 위치 임베딩이며 새 보정 구조의 차이가 아닙니다.

## 공통 경로와 명시적 문맥 전달

`models/TPPs/CountAwareTitanCNNGRU.py`는 기존 MLP16 모델을 생성한 뒤 새로
승인된 모듈만 교체합니다. 공통 모델을 생성하는 난수 소비는 동일하게 유지하며,
GRU 추가 초기화는 CPU 난수 문맥을 복원합니다. 기존 모델 파일과 공용 Factory,
학습기, 활성 폭8·12 실험의 동결 소스는 수정하지 않습니다.

CNN은 첫 블록의 Q/K/V 선형 투영 이후, 영구 메모리 K/V를 붙이기 전에
적용합니다. 64채널 각각의 현재·직전·두 번째 직전 **관측 사건**을 처리하는
독립 Q/K/V 커널 세 개를 사용합니다. 패딩은 사건으로 세지 않으며, 유효하지만
관측하지 않은 사건은 새 CNN 문맥 구간을 끊습니다. 영구 메모리와 기존
Attention 참조 범위는 유지합니다. 즉, 새 CNN 문맥의 초기화가 기존
Attention의 과거 참조 범위 전체를 지우는 것은 아닙니다.

`observed_context`가 계산한 관측 여부·과거 위치·가용성은 첫 블록과
Attention 호출 인자로 전달됩니다. 모델 속성에 배치별 마스크나 위치를 저장하지
않으므로 다른 표본이나 이후 호출이 이전 문맥을 받지 않습니다.

## 순환 보정

GRU 대조군은 기존 8분기 전체를 다음 식으로 교체합니다.

\[
z_i = P_{\downarrow}h_i,\qquad
s_i = \operatorname{GRU}(z_i,s_{i-1}),\qquad
\widetilde h_i = h_i + \mathbf1[\text{관측 구간 내 사건 수}\ge2]P_{\uparrow}s_i.
\]

투영은 편향 없이 64→54→64이며, 내부는 54차원 입력·상태의 단층 단방향
`torch.nn.GRU`입니다. GRU 편향은 유지하고 dropout은 0입니다. 상태와 관측
수는 매 호출의 표본별 접두 이력에서 0으로 시작합니다. 첫 관측은 상태를
갱신하지만 잔차는 내보내지 않습니다. 패딩은 상태·관측 수를 갱신하지 않고,
유효 미관측 행은 상태와 관측 수를 0으로 초기화합니다.

현재 구현은 위 마스크 계약을 그대로 표현하는 순차 GRU 호출을 사용합니다.
순차 실행 지연과 GPU 결정성·메모리는 원격 적격성 확인에서 실측해야 합니다.
파라미터 수가 MLP16과 가깝다는 사실은 처리 속도나 표현력이 같다는 뜻이
아닙니다. GRU54는 16차원 GRU가 아닙니다.

## 초기 출력과 체크포인트 구분

CNN 커널과 GRU의 위쪽 출력 투영은 0으로 시작합니다. 따라서 세 후보의
최초 출력은 같은 seed의 기존 MLP16 초기 출력과 일치합니다. 이미 학습된
MLP16 체크포인트를 새 구조로 바꿔 끼우거나 재학습 없이 변환하지 않습니다.

새 경로는 `cnn_gru_identity`와 명시적인 모델 이름·역할·메타데이터를
사용합니다. 기존 MLP용 구조 식별자는 새 후보의 state에서 제거합니다.
불완전한 state, 다른 보정 구조·폭·CNN 상태, 잘못된 평가 split·시간 출력부·
checkpoint 선택 기준·모델 역할은 로딩 전에 거부합니다. 기존 전체 CNN
후보가 쓰는 Q/K/V 커널 이름만으로 새 후보로 간주하지 않습니다.

`paper/scripts/run_titantpp_cnn_gru.py`는 명시적으로 호출했을 때만 해당
프로세스에 세 모델을 등록합니다. 기존 수량 log 손실, 양의 정수 반올림·하한
시간 likelihood, 전체 validation raw RMSE 선택, min40/max300/patience40을
유지합니다. CLI는 합성 자료 검증만 제공하며 실제 자료 학습을 자동 실행하지
않습니다.

## 남은 실행 경계

- 실제 검증 범위는 Taxi·Intermittent·RAF입니다. Instacart는 후속으로 둡니다.
- 기존 MLP16의 9조건을 재사용하고, 새 구조의 전체 대조는 27조건입니다.
- 폭8·12의 18조건 비교와 CPU 계약 검증 이후, 동결 소스·자료·GPU Runtime·
  파라미터·시간·메모리·실행 상한을 연결한 별도 실행 계약이 필요합니다.
- 이 구현이나 합성 테스트는 새 구조의 성능 개선·참신성·일반화를 확인한
  결과가 아닙니다. 학습과 최종 평가 결과는 별도로 남겨야 합니다.

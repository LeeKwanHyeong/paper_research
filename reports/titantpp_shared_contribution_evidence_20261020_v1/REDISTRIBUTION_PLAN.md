# 5090 종료 후 추가2seed 잔여 작업의 분할 실행 제안

상태: 계획만 작성. 사용자는 MAC 실험 종료 후5080에 남은 작업을5090에도 나누려는 방향을 제시했다. 이번 요청에서는 실행 목록·소유권·계약·scheduler·claim을 변경하거나 새 학습을 시작하지 않는다.

## 현재 기준선 — 완료 / 진행 중

- 5080은 공유형+외부6종 × 원본 세 데이터 × 추가seed72·82=42개를 최대3병렬로 진행했다. 기존42/52/62 결과와 분리한다. 마지막 조회19:33:17 KST의27완료·3진행·12대기는 과거 관측이며 분할 목록으로 재사용하지 않는다.
- 5090은 MAC9 정확도 작업이다.20:33:20 KST 완료 Validation 집계는5fit이며 MAC 전체 종료·Test·회수가 완료됐다는 뜻이 아니다.
- 5080의 기존 종료 대기 SSH 장애와 FINISH_STARTED/QUEUE_FAILURE/ACTION_REQUIRED를 보존한다. 기존 finisher를 그대로 재호출하지 않는다.

## MAC 작업의 실제 종료와 현재 유휴를 확인한다 — 다음 작업

- 대상:5090 MAC9. 학습9·Validation9·Test9의 scientific worker27개 및 dispatcher exit0, archive/manifest/선택·결과 SHA를 확인해 전체 완료를 판단한다.
- 완료 cache는 과거 상태다. 새 분할 실행 직전에 현재 GPU와 소유 프로세스의 실제 유휴를 별도로 확인한다. 진행 중 MAC child·평가·회수를 먼저 끝내며 MAC을 중단해서 자리를 만들지 않는다.
- 이 단계가 끝나도5080의 대기 작업이 이미 모두 시작됐거나 완료됐다면 분할을 실행하지 않는다.

## 같은 과학 조건으로 나눌 수 있는 미시작 작업을 확정한다 — 다음 작업

- 대상:5080 추가42. 그 시점의 완료·진행·미시작 ID를 한 번 확정한다. 현재 실행 중인 fit과 완료 checkpoint는5080에서 그대로 유지한다.
- 5090에는 아직 시작하지 않은 과학 job ID만 배정한다. 기존 대기 목록을 복사한 뒤 양 서버가 동시에 가져가는 방식은 쓰지 않는다. 기존 claim/failure 삭제나 기존 기록의 host 변경도 하지 않는다.
- 원본 데이터·입력 SHA·모델 source·seed·head·손실·optimizer·batch·학습 예산·Validation 선택·기존 절대 기한을 유지한다. fresh fit만 나누며 warmstart나 추가 seed를 만들지 않는다.
- 같은 모델의 추가 두 seed가 특정 GPU에만 편중되지 않도록 가능한 배분을 검토하고 실제 host·Python/torch/cuDNN/GPU를 결과에 기록한다.5090/cuDNN92000와5080/cuDNN91900 차이를 숨기지 않는다.

## 별도 제어 경로와 회수 병합 기준을 검토한다 — 다음 작업

- 기존42 계약은5080 배정이므로 host 문자열을 고쳐 덮어쓰지 않는다. 기존 과학 조건과 실패를 상속한 새 제어 계약에서 미시작 ID의 배정·단일 소유권·중복 차단을 명시한다.
- 먼저5080이 양보할 ID와5090이 가져갈 ID를 상호 배타적으로 고정해야 한다. 최대 동시 학습은 서버당3개다. 모델별 개수보다 해당 fit의 실제 최근 속도와 남은 기한을 보고 분할 이득을 판단한다.
- 각 host에서 학습→고정 checkpoint Validation 재현→Test의 검증 관계를 보존하고, 최종적으로 원래42개 고유 ID만 한 번씩 집계한다. 완료·선택·worker exit·archive/manifest·원본 SHA와 중복/누락0을 확인한 뒤5seed 보고서를 만든다.
- 기존3seed와 기존5seed 준비 도구는 원본 그대로 두고 새 병합 증적을 별도 경로에 쓴다. 기존 연결 실패를 성공으로 덮어쓰지 않는다.

## 구체적 분할 목록과 실행 변경을 확인한다 — 승인 필요

- 확인할 대상은 실제 미시작 job ID 목록, 서버별 배정, 별도 제어 경로,5080 대기열의 해당 ID 양보 방식,5090의 신규 실행·평가·회수 범위다.
- 구체적인 계획이 확정된 뒤 해당 변경을 승인받고 구현·검증·실행한다. 현재 방향 제시만으로 queue ownership 변경이나 새 연결 복구를 실행하지 않았다.
- 이 제안에는 공용 Runtime/driver/auth 변경, 기존 학습 중단·재시작·자동retry, claim/failure 삭제, 기한 연장, 데이터 재가공이 포함되지 않는다.

## 완료 조건 — 후속 실행 시 적용할 제안

- 원래42개 ID에 완료·진행·미시작의 누락/중복0, 새로운 과학 fit ID0.
- 기존3seed 및 중단 작업·checkpoint·원본 실패 보존.
- 모든 신규 결과의 host provenance와 종료·선택·회수 SHA 검증.

- 현재 문서 단계에서는 원격 조회0·GPU 실행0·제어 코드 변경0·scheduler 변경0이다.

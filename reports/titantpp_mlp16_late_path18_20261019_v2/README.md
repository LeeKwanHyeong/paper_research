# 손실 비교 직후 MLP16 백본18 실행

사용자 최신 지시에 따라 **원시간 입력27개는 보류**하고, 현재 손실 비교 완료 뒤 두 백본 후보를 바로 학습한다. 시간·수량 입력은 기존log1p로 고정하고 공통 손실만 선택한다.

**실행 순서 변경 — 완료**

- 원시간27 대기와 구백본18 대기는 신원확인 후 로컬 정지T 상태다. 원본과 기존 준비는 보존했다. 현재 손실 학습·완료 처리·서버 프로세스·기존CNN은 변경하지 않았다.
- 이전 작업에서 이어받은 과학모델·worker는 동일바이트다. 현재 관측을Encoder뒤·기존메모리앞으로직접전달하는 후보와,같은명목용량의이력대조를 비교한다.

**다음 연결 검증 — 완료 / 실제 연결 다음 작업**

- 현재 손실18의학습·선택Validation18·원본회수·저장log손실9개를포함한27개비교가완료돼야 공통손실을선택한다. 원시간실험 결과는요구하지않는다.
- log-MSE/실수량MSE/실수량MAE 중 세데이터의 기준선대비RMSE비율 평균이최소인손실 하나를 고른다. MAE는정확동률처리이며 모든점수와seed를보존한다.
- Cap3데이터×3seed×두후보=18개:5080에8개,5090에10개,서버당최대3병렬이다. 같은조건의MLP16저장9개와Validation RMSE/MAE·모든seed차이·악화를비교한다.
- 새학습진입전실제GPU/Runtime/입력/3동시검증을하고,동일예산·기한·선택기준을유지한다. Test·새baseline학습·기존CNN변경·자동재시도·반복스케줄러는없다.

실제 연결은 LOCAL_READY.json과 FOLLOWUP_STARTED.json, 실행 시작은 START_RECEIPT.json, 최종 완료는 followup_v1/complete.json 및 회수final_receipt.json으로 구분한다. 이문서의준비상태를 실제학습시작으로표현하지않는다. 자세한순서는 EXPERIMENT_PLAN.md와 최신 REGISTERED_STATUS.md를 따른다.

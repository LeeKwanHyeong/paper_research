# KeyContent 저장 행 독립 집계와 해석 검토

**원본과 산술 검증 — 완료**
- PASS_independent_saved_row_recalculation. 705개 입력 raw SHA를 검사 전후 확인했다. 현재 비교기를 실행하지 않고 별도 계산으로 97,407쌍(총194,814행)을 재집계했다.
- Train25,779·Validation6,690 대상과 관측 이력을 원입력에서 재구성했다. 새 onValidation20,070행은 기존 on행과 대조했고, 한 관측15,000쌍의 예측·TimeNLL은 정확히 같다. 조건 간 parameter/buffer/context 상태·Runtime과 checkpoint 선택도 일치한다.
- 고정15조건·180개 seed별 가중 집계·90개 지원행·1,560개 평균/표본SD 값·AE/SE/부호오차36개 가산 등식·12개 여섯지표 요약을 검산했다. 열린 발견은 없다.
- 검토자는 이번 설계 검토와 이전 KeyHistory 명세 작성에 참여했으며, 이번 검토는 구현 작성자와 독립된 결과 산술 검증이다. native 실행 감사는 별도 담당이다.

**다음 단일 학습 가설 — 미확정**
- 가용 계수 합을 유지해도 상충이 남으므로 직전 삭제 진단의 상충을 계수 합 변화만으로 설명하기는 어렵다. 다만 실제 K의 크기·방향·attention·메모리 경쟁은 분리되지 않았다.
- 과거 내용은 현재 고정 가중치에서 MAE·시간 측면의 유용성과 RMSE·큰수량 측면의 비용을 함께 보인다. 이것만으로 제거·gate·norm·긴 필터 중 하나를 선택할 수 없다.
- LevelHistory의 수준/차분, V-difference의 차분 제약, Adaptive의 이력별 재가중, MultiLag의 여러 범위, Query/KeyOnly의 위치 분리를 이름만 바꾸어 반복하지 않는다. 자유로운3tap을 수준/차분으로 다시 쓰는 것만으로 새 표현력이 생기지 않는다.
- 즉시 새 모델을 학습하면 구현·GPU 비용과 사후 선택 위험이 추가된다. 현재는 결과를 보존하고 다음 구조를 미확정으로 남기는 판단이 적절하다. 같은 DC·삭제·내용 제거 진단이나 임의 배율 탐색은 더 권하지 않는다.
- 이후 학습을 정하려면 MAE·시간의 이득을 유지하면서 RMSE 비용을 줄인다는 별개의 구조적 근거와 대조가 먼저 필요하다. 이번 결과가 그 구조를 특정하지는 않는다. 원인 확정·독립 일반화·새 원리·재학습 성능을 주장하지 않는다.

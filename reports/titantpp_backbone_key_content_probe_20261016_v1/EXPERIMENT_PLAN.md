# KeyOnly 과거 내용과 가용 계수 합을 구분하는 단일 진단

**현재 기준선과 남는 질문을 고정한다 — 완료**
- 대상은 `paper_research`의 KeyOnly seed42/52/62, 선택 epoch9/5/26이다. 기존 CNN·QueryOnly·학습 원본은 유지한다.
- 직전 과거 tap 삭제는 Validation 평균 RMSE를 0.039180 낮추고 MAE를 0.013672 높였다. Train도 RMSE 개선·MAE 악화였다. 공통 개체 가중의 Train seed52 RMSE는 예외로 소폭 악화했고 시간 지표도 악화했다.
- 과거 내용을 제거하면서 계수 합도 바뀌었으므로 과거 혼합 자체가 오류 원인이라고 결론 내릴 수 없다.

**같은 계수 합을 유지한 내용 대조를 명세로 묶는다 — 완료**
- 원형은 `K0+w0*K0+I1*w1*K1+I2*w2*K2`이고 대체 조건은 `K0+w0*K0+I1*w1*K0+I2*w2*K0`이다. I1/I2는 각 event 위치별 실제 가용성이다.
- 원본 w0는 그대로지만 대체 조건의 유효 현재계수는 w0+I1*w1+I2*w2가 된다. 가용 계수 합과 잠재 상수 응답을 보존하며, 실제 K 출력 크기·방향이나 attention 배분은 보존하지 않는다. 투영으로 흡수할 수 있다는 설명도 평가 함수 수준이며 재학습 효과까지 같다는 뜻은 아니다.
- 두 조건의 차이는 `I1*w1*(K1-K0)+I2*w2*(K2-K0)`다. 없는 과거 tap은 추가하지 않으며 padding/withheld 경계를 그대로 적용한다.
- 원형 전체 검사를 먼저 통과한 뒤 임시 source index만 대체한다. 실제 가중치·입력·head·메모리·Runtime은 바꾸지 않는다.
- 명세 SHA `f8ce822618bc0dcbacda3512215a9e368afb054a26466616cca1089b12d18678`, 검증 조건 SHA `6520d428c1cd3c4ac4f211c2c4e89a6b5b570d4efe22cf4c64ff73a948771d2e`. 코드·실행 준비 완료를 뜻하지 않는다.

**새 진단 도구와 합성 검사를 구현한다 — 다음 작업**
- 새 파일과 새 격리 경로만 사용한다. exporter/집계기는 별도 파일 소유로 병렬 구현할 수 있지만 공통 계약·독립검토·봉인은 순서대로 진행한다.
- 상수/변동 K, 관측1·2·3개, padding/withheld, 원래의 잘못된 과거 값·index·kernel, 상태·함수 복구를 검증한다.
- 내용 대체를 새로운 모델로 부르지 않는다. 선형 수준/차분 분해는 기존 자유3tap의 재표현일 수 있고 LevelHistory·Vdifference·Adaptive·MultiLag와 중복을 확인해야 한다.

**5090의 원형 Validation 재현 뒤 대체 조건만 평가한다 — 다음 작업**
- 독립검토·봉인·GPU/Runtime/입력·소유 검증 후 qualification3 → 새 onValidation3 → offTrain3 → offValidation3, 최대3병렬로 1회 실행한다.
- 새 onValidation은 기존 on 개별행의 수량 예측·시간 손실·여섯 지표·대상을 모두 재현해야 한다. 기존 onTrain3은 원본·state·대상 검증 후 재사용하고 재평가하지 않는다.
- 새 실데이터 worker9, qualification3, 총worker12다. 상속 deadline1792679647.915156은 연장하지 않는다.

**고정된 조건으로 비교하고 다음 가설 하나를 판단한다 — 다음 작업**

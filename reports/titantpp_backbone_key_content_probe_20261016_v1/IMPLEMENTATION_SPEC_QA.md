# KeyContent 구현–명세 독립 대조

**구현 경계와 합성 검증 — 완료**
- PASS_implementation_spec_alignment. 작성자와 독립된 검토이며, 검토자는 이번 명세의 설계 검토와 이전 KeyHistory 명세 작성에 참여했다.
- 고정된 합성 57검사를 독립 실행해 실제 exit0를 확인했다. 입력 4파일의 전후 SHA는 같다.
- 별도 임의 유한 계수·padding/withheld 경계 40사례에서 가용 계수 합, 단일 관측·상수 잠재 K 응답, 원본 인자 및 함수 복원을 확인했다.
- 불균등한 개체별 행 수를 둔 수계산으로 두 가중방식을 대조했고 180집계·90지원행·12가산 검산을 확인했다. 예측·시간손실 재현과 역할/이력 변경 거부도 확인했다.
- 원형 함수를 먼저 호출하고 임시 source index만 대체한다. 선택된 KeyOnly3, 저장 onTrain 재사용, onValidation3 행별 예측·TimeNLL 재현, 전3 gate, 관측 이력과 역할별 행 대응은 명세와 일치한다. 열린 발견은 없다.

**해석 및 검증의 한계 — 현재 기준**
- 원본 w0는 같지만 유효 현재 계수는 가용한 계수 합이다. 잠재 상수 응답 보존이 실제 K 크기·방향·메모리 attention 보존을 뜻하지 않는다.
- 로컬 torch2.14.0 합성 결과이며, 지정된 5090 torch2.11.0/cuDNN92000의 실제 검증을 대체하지 않는다. 운영 생명주기 검토는 별도 담당이다.
- 원격·실데이터 추론·기존 CNN/Query 추론·Test 열람·새 학습·소스 수정은 하지 않았다.

**새 진단 실행 전 검증 — 다음 작업**
- 운영 독립 검토와 최종 봉인을 결합한 뒤 native 조건을 확인한다. 원형 Validation3 재현을 모두 통과한 경우에만 offTrain3/offValidation3으로 진행한다.
- 실제 결과가 나오기 전 다음 backbone이나 새 학습을 확정하지 않는다.

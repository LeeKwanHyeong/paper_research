# 다음 후보 준비: 검색된 prototype의 반영량 제어

## 상태와 목적

- 상태: 연구 설계 준비. 구현·새 학습·원격 실행은 미실행. 최종 실행 계약이나 성능 보장이 아니다.
- 목적: 현재 이력과 맞지 않거나 과도한 prototype 보정이 수량 예측을 악화시키는지, 관측 이력만으로 반영량을 조절해 그 손해를 줄일 수 있는지 검증한다.
- CAP의 정확한 결론: FULL 대비 일부 완화는 있지만 CNN 대비 평균 Test 우위와 순위 반전 해소는 실패했다. 이 결과로 메모리가 원인이라고 추론하지 않는다.
- 기존 결과: 대표 모델9, 보정27, Instacart9, 구성요소36, CAP9, retrieval pilot은 각각 보존한다.

## 이번 후보가 다루는 문제

공통 backbone 문제를 다루기 위해 **CNN 구조를 고정한 대조**를 우선한다. FULL의 GRU 손해와 CNN 자체의 외부 모델 대비 손해를 동시에 고치려 하지 않는다. CNN 선택은 Test 이후의 연구 설계이므로 탐색적 후속이라는 이력을 유지한다.

Taxi에서 CNN은 S2P2보다 하락 조건 과대예측이 크다. 반면 FULL 대 CNN의 주요 손해는 상승 조건 과소예측이다. 이번 메모리 후보가 겨냥하는 우선 문제는 전자다. 내부 GRU 대조의 설명을 그대로 전자에 적용하지 않는다. RAF·Intermittent는 이득의 전이와 악화 여부를 확인할 대상이며, 유리한 데이터셋만으로 최종 모델을 정의하지 않는다.

이미 완료된 contextual retrieval pilot은 검색 점수에서 시간·수량 query 비중을 바꿨다. 이번 후보는 top-k 선택과 평균 검색을 유지한 채 **최종 residual 주입량**을 다룬다. 두 변경을 한 번에 넣지 않는다.

## 1. 고정 모델에서 가설의 근거를 확인한다 — 다음 작업

대상은 기존 선택 CNN checkpoint의 Train/Validation이다. 원본은 수정하지 않고 별도 진단 산출물을 만든다. Test로 gate·배율·threshold를 고르지 않는다.

- encoder 상태 h, 실제 검색 residual m, 두 벡터의 norm 비율과 cosine, 검색 점수의 간격·집중도, 관측 이력 안에서 검색 결과의 변동을 기록한다.
- 고정 배율 alpha={0, 0.25, 0.5, 1}로 h+alpha*m의 민감도를 본다. 이는 추론 중 개입이며 원래 학습 분포와 달라진다. 원 모델 성능을 대체하거나 새 모델의 학습 성과로 보고하지 않는다.
- 전체 raw RMSE·MAE, Train 고정 큰 수량 RMSE·MAE, 두 TimeNLL을 같은 모델에서 보존한다. seed별 원값, 대상 수, paired MSE/절대오차 차이를 함께 기록한다.
- 실제 미래 target을 이용한 상승·하락 구분은 사후 진단에만 사용한다. gate 입력에는 과거 관측과 현재 encoder/retrieval 신호만 허용한다.
- cosine이나 top-k 점수 차이는 후보 신호이지 보정 유용성의 검증된 확률이 아니다. 전처리 통계는 Train에서만 얻는다.

**진행 조건:** 고정 감쇠가 손해를 줄이는 양상이 있고, 그 양상이 예측 전에 계산 가능한 특징과 연결되는지 확인한다. seed별 결과가 엇갈리거나 시간/꼬리 손해가 크면 그대로 기록한다. 정확한 수치 채택 기준은 진단 결과를 Test와 혼합하지 않고 후속 학습 계약에서 사전에 확정한다.

**중단 또는 방향 전환 조건:** 메모리 감쇠와 오류 변화가 거의 연결되지 않거나, 손해 구분에 미래 target이 꼭 필요하면 adaptive gate의 근거가 부족하다. 이 경우 메모리 gate를 바로 학습하지 않는다. 상수 감쇠만 유용하다면 복잡한 adaptive 설계가 필요한지도 재검토한다.

## 2. 변경 하나를 식별하는 대조를 설계한다 — 다음 작업

가능한 형태는 h'=h+g(z)*m이며 z는 예측 전에 관측 가능한 이력·검색 특징이다. g(z)를 [0,1]로 제한하는 것만으로 실제 residual norm이 제한되는 것은 아니다. 학습 중 memory value가 커질 수 있으므로 실제 주입 비율을 기록하고 설계 목적과 일치하는지 확인한다. norm 제한까지 넣으면 별도의 변경이 되므로 무심코 결합하지 않는다.

| 대조 | 확인할 질문 |
|---|---|
| 변경 없는 CNN·uniform top-k memory | 동일 source·Runtime·학습 계약 아래 기준선이 재현되는가? |
| CNN·고정 감쇠 memory | 반영량을 줄이기만 해도 좋아지는가? |
| CNN·관측 이력 기반 adaptive gate | 고정 감쇠보다 조건별 제어가 추가 가치를 주는가? |

기존 CNN 결과는 역사적 기준선으로 유지한다. 새 구현을 공정하게 비교하려면 변경 없는 arm도 같은 실행 계약에서 필요할 수 있다. 그 fit 수를 숨기거나 기존 결과를 새 결과로 덮어쓰지 않는다. gate의 추가 파라미터를 보고하고, 중요할 경우 일반 learned gate/동일 활성 파라미터 대조가 필요한지 최종 계약에서 결정한다.

유지할 조건: CNN/attention 구조, memory 크기·top-k, head·손실, 데이터와 preprocessing, seed42/52/62, Validation 첫 strict finite 최소 raw 수량 RMSE checkpoint 선택, 동률 최초 epoch, 기존 학습 예산 정책. 별도 rho 탐색·GRU 재도입·head 변경을 섞지 않는다.

다른 비교군은 S2P2와 AttNHP를 포함한 기존 외부 패널 및 강한 내부 MLP를 보존한다. 기존 결과는 과거 캠페인의 맥락 비교다. 모든 후보를 같은 조건에서 새 학습했다고 표현하지 않는다. 외부 baseline 전체 재학습은 이번 준비 범위에 포함하지 않는다.

## 3. 반증 가능한 판정 기준과 독립 평가를 고정한다 — 다음 작업

- 주 판정은 전체 raw RMSE이며 MAE·큰 수량·TimeNLL의 악화와 3seed 차이를 함께 본다.
- adaptive와 고정 감쇠가 비슷하면 '상황에 따른 기억 제어가 필요하다'는 주장을 채택하지 않는다. Test 평균 하나만 좋아졌다고 자동 채택하지 않는다.
- 관측 가능한 특징으로 미리 정한 위험 조건에서 오류와 편향이 줄고, 다른 조건에 손해를 옮겼는지 검증한다. 목표를 보고 만든 조건은 설명용으로 별도 유지한다.
- 실용적 효과 크기와 비용 한도는 실행 전 고정한다. 아직 정하지 않은 수치를 봉인된 기준처럼 제시하지 않는다.
- 새로운 미노출 기간·데이터 또는 사전에 잠근 시간 순서 평가의 가능성을 먼저 확인한다. 기존에 본 사건을 재분할한 것만으로 미노출 독립 평가가 되지는 않는다.
- 신규 확인 자료가 없다면 같은 Test 결과는 탐색적으로만 보고한다. 이 한계가 있으면 모듈이 개선되더라도 보편적 일반화 해결을 주장하지 않는다.
- 비교 목적에 맞는 공통 달력 시점 분할이 필요한지 결정한다. 현재 개체별 분할을 바꾸는 작업은 별도 계약이며 기존 결과는 그대로 보존한다.

## 4. 구현·합성 검증·실행 순서 — 구현은 다음 작업, 원격 학습은 승인 필요

프로젝트 `paper_research`에서 별도 모듈·실험 경로를 사용한다. 기존 동결 source, 학습 root, claim/failure, checkpoint를 바꾸지 않는다.

1. 진단 결과를 바탕으로 gate 입력·수식·대조·fit 수·GPU 배정·예산·중단 기준을 확정한다.
2. 합성 입력으로 target 차단, prefix 인과성, padding, g=0/1 경계, batch 일치, finite 출력·gradient, 평가 중 파라미터 불변을 검증한다.
3. 원래 memory 주입(g=1)이 기존 구현과 일치하는지 확인한다. 임의 임계값 선택이나 실제 Test 디버깅을 하지 않는다.
4. 새 학습의 구체적 실행 승인을 받은 뒤 GPU·Runtime·입력 SHA 검증과 제한된 native 검증을 수행한다. 기존 CAP 학습 승인은 재사용하지 않는다.
5. 고정 계약으로 3seed Validation을 비교하고 모든 결과·실패를 보존한다. 사전에 정한 다음 평가 경계에 도달하면 그 계약대로 진행한다.

현재 준비는 이 문서까지다. 아직 구현 검증, 새 데이터 확보, 진단 실행, 학습이 완료됐다고 보고하지 않는다.

## 논문 기여가 되려면 남겨야 할 증거

단순 gate 추가는 ReZero·TFT 등 기존 gating 연구와 구분되는 충분한 신규성이 아니다. 현재 후보가 기여가 되려면 '어떤 관측 신호에서 어떤 memory 주입이 손해를 만들며, 제어가 고정 감쇠보다 왜 유용하고, 어디까지 재현되는가'를 보여야 한다. 효과가 확인되지 않으면 부정적 결과로 보존하고 모듈을 계속 덧붙여 성공한 Test만 고르지 않는다.

방법론 강화와 별도로 실패 분석을 중심으로 한 논문도 검토할 수 있다. 이 경우 운영상 의미가 있는 평가와 다른 조건에 적용 가능한 교훈이 필요하다. 둘 중 어느 경로도 현재 자료만으로 채택을 보장하지 않는다.

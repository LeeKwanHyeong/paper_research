# RAF 후속 가설: 이력 길이별 보정 민감도를 제한하는 Shared15

**판정: 가설 하나로 설계 검토 완료. 가중치 상한 확인 완료. 보수적 축소의 문제를 확인해 이 수식 그대로의 학습 진입은 보류.**

기존 Shared15의 관측 표현과 큰 수량 예측 경로를 유지하면서, 이력 보정이 관측 표현의 변화를 과하게 증폭하지 않도록 제한한다. 이력 길이에 따라 달라지는 활성 분기 조합마다 같은 상한을 적용한다. 급락 오류의 원인이나 개선 효과가 확인됐다는 결론은 아니다. 현 단계에서는 이 조건부 가설 하나를 남긴다. 추가한 저장 가중치 분석에서 긴 이력 조합을 점검할 근거와 제안 수식의 과도한 축소 위험을 함께 확인했으므로, 아래 Frobenius 수식을 학습안으로 채택하지 않는다.

이 문서는 내부 설계 자료다. 기존 실험·자동 회수·CNN·모델 source·checkpoint·결과·실패 기록·원고는 변경하지 않았다. 이번 작업에서 새 학습·모델 추론·원격 접속·Test 열람은 모두0이다. 원본 Shared15의 선택 checkpoint3개만 CPU weights_only로 읽어 가중치 norm을 계산했다. 모델 인스턴스와 forward는 생성·실행하지 않았다. 처음의 독립 설계 검토는 이 분석 전 자료로 보존한다.

## 1. 현재 기준선과 해결할 오류 — 완료

직전 [RAF 진단](../titantpp_raf_shared_error_diagnosis_20261021_v1/REPORT.md)은 현재 Shared15와 외부 비교군의 저장 Train·Validation 자료를 분석했다. 아래 개별 행 수치는 **공유형 seed42·52·62의 같은 Validation 6,690행**이다. 추가 seed72·82의 개별 예측을 포함한 5seed 행 진단으로 표현하지 않는다. 현재 Shared15의 Train 개별 예측은 없어 Train–Validation raw오류로 과적합을 판정할 수 없다.

| 관측된 현상 | 확인한 근거 | 이번 가설과의 연결 및 한계 |
|---|---|---|
| 큰 수량 예측에서 RMTPP보다 유리 | q>200의 50행에서 Shared RMSE/MAE 325.510/279.210, RMTPP 338.945/293.393 | 기존 이득을 버리는 전반적 축소를 성공으로 인정하지 않는다. S2P2는 324.312/277.715로 Shared보다 조금 낮다. |
| 급락 뒤 상대적 과대예측 | 실제 다음 수량≤직전 관측 수량/5인 577행에서 Shared MAE16.646806, RMTPP14.542938. 세 seed 모두 Shared가 불리 | 현재·직전 표현을 읽는 보정의 과도한 반응을 점검할 이유다. 다음 급락 여부는 입력에서 알 수 없고, 내부 증폭이 원인인지는 미확인이다. |

큰 수량 50행은 Shared 제곱오차 합의 68.638%를 차지한다. 이 구간을 악화시키고 급락 MAE만 개선하는 방법은 현재 질문에 맞지 않는다. 두 구간은 미래 정답으로 나눈 **사후 진단 집단**이며 학습 입력이나 gate로 사용하지 않는다.

## 2. 이력 길이가 달라질 때 실제로 무엇이 바뀌는가 — 완료

현재 [SharedHistoryCorrection](../../models/TPPs/CountAwareTitanSharedHistoryMLP.py)은 첫 Encoder block의 현재 표현과 **즉시 직전 관측의 표현**으로 같은 관계 특징을 한 번 만든다. 분기마다 서로 다른 과거 lag를 읽는 구조가 아니다. 첫 Encoder의 attention이 이미 처리한 전체 이력과 이 추가 국소 보정을 구분한다.

| 항목: 예측 대상의 마지막 관측 위치 기준 | Train | Validation |
|---|---:|---:|
| 관측 이력 중앙값 / 최대 | 3 / 14 | 7 / 16 |
| 활성 분기 평균 | 1.763 | 3.032 |
| 네 번째 분기 활성: 관측 이력>8 | 809/25,779, 3.138% | 1,690/6,690, 25.262% |

활성 문턱은 [1,2,4,8,16,32,64,128]이며, 문턱16 이상인 뒤쪽 네 분기는 두 split에서 사용되지 않는다. Validation은 네 번째 출력 분기를 포함한 합을 약8.05배 자주 사용한다. 실제 MSE 분해에서도 이력9개 이상 구간이 Shared−S2P2 차이에 +17.295709를 기여했다. 그러나 이 구간의 수량 구성도 다르므로 **분기 사용 빈도 변화가 오류 원인이라는 증거는 아니다.**

기존 보정을 수식으로 쓰면 다음과 같다. U는15×128, B_j는64×15, z는 첫 block의 현재·직전 표현을 연결한128차원 벡터다. k는 기존 조건을 만족하는 앞쪽 연속 분기의 개수다.

\[
C_k=\frac{1}{8}\sum_{j=1}^{k}B_j,\qquad R_k(z)=C_k\operatorname{GELU}(Uz),\qquad C_0=0.
\]

첫 block 출력에 R_k를 더한 뒤 두 번째 block과 기존 후단 memory를 처리한다. 따라서 **각 B_j가 아니라 실제로 사용되는 합 C_k 전체**를 제한해야 이력 길이별 조합에 같은 민감도 상한을 적용할 수 있다. 기존 `/8`과 가용 조건은 유지한다.

## 3. 남긴 가설 하나와 검토한 적용 수식 — 설계 완료·수식 채택 보류

> 같은 현재·직전 표현 변화가 만드는 이력 보정의 증폭을 활성 분기 조합별로 제한하면, 기존 큰 수량 이득을 유지하면서 RAF 급락 구간의 상대적 MAE 약점을 줄일 수 있는가?

새 모듈을 추가하지 않고 Encoder1과 Encoder2 사이의 Shared15 보정만 아래 함수로 바꾸는 안을 검토했다. 아래 식의 수학적 상한과 현재 오류를 줄일 실용성은 다른 문제다. 6절의 가중치 검사 결과에 따라 **이 식 그대로의 구현·학습은 권하지 않는다.**

\[
a_k=\left(\frac{\gamma}{L}\right)^2\|U\|_F^2\|C_k\|_F^2,
\quad s_k=\frac{1}{\sqrt{\max(1,a_k)}},
\quad R'_k(z)=s_k R_k(z),
\quad L=1,\ \gamma=1.25.
\]

k=0에서는 R'_0=0,s_0=1이다. s_k는 **해당 조합의 학습 가중치만**으로 계산한다. 같은 k의 모든 입력에 같은 s_k를 적용한다. 관측 수량 크기·수량 차분·급락 정답을 보고 조절하지 않는다. L=1은 hidden pair 변화보다 큰 보정 민감도를 허용하지 않는 설계 기본값이며, 데이터에서 최적임이 확인된 수치가 아니다. Validation을 보고 L을 탐색하지 않는다.

고정 가중치와 고정 k에서 다음 상한이 성립한다.

\[
\|R'_k(z)-R'_k(\tilde z)\|_2\le L\|z-\tilde z\|_2.
\]

이는 exact GELU의 도함수 절댓값이 1+1/√(2πe)<1.25이고, 행렬의 operator norm이 Frobenius norm 이하라는 성질에서 도출한 **보수적인 충분조건**이다. [GELU 정의](https://docs.pytorch.org/docs/2.11/generated/torch.nn.GELU.html)와 [matrix norm 정의](https://docs.pytorch.org/docs/2.11/generated/torch.linalg.matrix_norm.html)는 공식 문서를 따랐다. 이번 식은 정확한 spectral normalization이 아니다. 가중치 norm으로 입력 민감도를 줄이는 일반 원리는 이미 [Yoshida·Miyato(2017)](https://arxiv.org/abs/1705.10941)에 존재한다. RAF 효과나 방법론 신규성의 근거로 그 논문의 다른 데이터 성능을 전용하지 않는다.

**보장 범위 밖:** 전체 Encoder·head·raw수량 예측의 민감도, k 변경 시 연속성, 다음 급락 감지, 큰 수량 이득 보존, 실제 일반화 성능. 다른 층이 보상할 수 있고 같은 제한이 큰 수량에도 적용된다. 보정 출력의 방향을 유지하는 scalar 제한이라는 사실도 최종 예측 방향 보존을 보장하지 않는다.

## 4. 기존 시도와 무엇이 겹치고 다른가 — 완료

[21개 축의 코드·계약 감사](OVERLAP_AUDIT.json)는 구현 존재와 일부 준비 상태를 확인했다. 모든 후보의 native 완료·성능을 다시 검증한 감사는 아니다.

| 기존 축 / 대안 | 이번 판단 |
|---|---|
| ActiveBranchNorm: 활성 수로 나누기; 전체 분기 활성화; current-only | 이미 구현된 개입이다. 이번에는 기존 `/8`·문턱을 유지하고, 가중치가 만드는 각 합의 민감도만 제한한다. |
| AdaptiveHistory의 bounded tanh 보정, GRU residual L2 cap, Q/K 상대 norm cap | 보정 크기 제한이라는 일반 안정화 아이디어는 이미 있다. 이번 대상은 Shared15의 합성 함수가 hidden pair 변화에 반응하는 상한이다. 적용 위치와 함수 제약은 구별되지만 일반적인 cap 자체를 새 원리로 주장하지 않는다. |

검토 범위에서 Shared15의 **활성 조합별 입력 민감도 상한**을 강제하는 동일 구현은 찾지 못했다. 저장소 전체 부재나 세계적 신규성을 입증한 것은 아니다. 이 후보는 현재 보정 경로에 학습 제약을 두는 설계이며, 완전히 새로운 backbone 계열로 포장하지 않는다.

## 5. 초기화·미사용 분기·비용을 보존하는 조건 — 구현 전

- 추가 학습 파라미터0, 보정 파라미터9,600개 유지. U·B_j·공통 Encoder/head/memory 초기 tensor와 RNG를 보존한다. B_j=0이면 a_k=0,s_k=1이므로 초기 출력과 초기 B_j gradient가 기존과 같아야 한다.
- 각 위치는 자신의 s_k만 사용한다. j>k인 B_j에는 그 위치에서 출력·상한 gradient가 흐르지 않아야 한다. 전체 prefix의 최대 norm으로 만든 공통 s는 미사용 분기까지 gradient가 흐를 수 있어 **초안에서 폐기**했다.
- squared sum→clamp_min(1)→rsqrt의 미분을 사용한다. denominator detach나 optimizer 이후 projection을 섞지 않는다. zero/nearzero/경계의 finite gradient는 아직 검사하지 않았다.
- 기존 보정 출력은 기존 concat/F.linear와 `/8` 연산 순서를 유지하고 C_k는 상한 계산에만 사용하도록 제안한다. C_k로 출력을 다시 계산하는 대수적 재표현이 부동소수점에서 같은 비트값을 보장한다고 주장하지 않는다.
- 추가 연산은 작은 가중치 행렬의 prefix 누적과 제곱합이다. 추론 시 고정 가중치의 s_k는 재사용할 수 있지만 실제 속도·메모리는 미측정이다. 이 설계만으로 효율 개선을 주장하지 않는다.
- Frobenius 상한은 실제 operator norm보다 훨씬 클 수 있다. 불필요한 일괄 축소가 될 위험이 가장 크다.

## 6. 학습 전 가중치 검사와 실제 판정 — 완료

**저장 Shared15 가중치만으로 기전의 최소 근거를 확인했다.** 아래 사전 설계 조건을 보존하며, 결과를 보고 상한 L이나 진입 기준을 완화하지 않았다.

1. 기존 seed42·52·62 선택본의 정확한 checkpoint/source lineage를 검증하고 CPU에서 U,C_1…C_8의 Frobenius norm과 최대 singular value를 읽는다. 원본 파일은 그대로 둔다.
2. 실제 사용 prefix k=1…4의 제안 s_k와, 더 촘촘한 충분상한 γ||C_k||₂||U||₂를 보고한다. 가중치 norm만으로 실제 입력별 Jacobian이나 급락 원인을 확정하지 않는다.
3. 사용 prefix 모두에서 제안 상한이 비활성이면 현재 오류를 겨냥할 근거가 약하므로 새 학습을 보류한다. operator 기반 충분상한은≤1인데 Frobenius 보수성만 축소를 유발하는 경우도 진입을 보류한다.
4. 충분상한이1을 넘더라도 실제 증폭을 증명한 것은 아니다. 이때에만 후보 구현·합성 검사로 넘어갈 근거가 생기는지 판단한다. 수치를 보고 L을 바꾸거나 다른 cap 후보들을 자동 탐색하지 않는다.

실제 분석은 `WEIGHT_NORM_ANALYSIS.py`로 한 번 실행했다(actual exit0). 선택 epoch9/5/19, checkpoint binary SHA와 canonical tensor SHA를 기존 SOURCE_MAP에 대조했고, 세 원본 binary SHA의 전후 불변을 확인했다. CPU float64 행렬 계산만 했으며 새 예측·평가가 아니다.

| seed | 네 번째 조합의 operator 기반 충분상한 | Frobenius 기반 충분상한 | 제안 식이 만드는 s_4 |
|---|---:|---:|---:|
|42|1.836383|4.953035|0.201896|
|52|1.306721|2.963473|0.337442|
|62|4.085127|7.890192|0.126740|

세 seed 모두 긴 이력 조합에서 operator norm 곱의 충분상한이1을 넘는다. 이는 가설을 검토할 이유이며 **실제 Jacobian이1보다 크거나 급락의 원인이라는 증거가 아니다.** 선택된 checkpoint만 조사했으므로 학습 전 과정의 상태도 설명하지 않는다.

더 중요한 반대 근거도 나왔다. seed42의 k1은 operator 기반 상한0.747814인데 Frobenius 상한1.643450으로 제안 s1=0.608476이다. seed52의 k2/3도 operator 상한0.714224/0.796797인데 Frobenius 상한1.602931/2.104501 때문에 축소된다. 즉 이미≤1로 보장되는 짧은 이력까지 이 수식은 줄인다. 긴 이력에서의 s4도0.127~0.337로 보수적 축소가 크다.

**판정:** 입력 민감도 제어라는 단일 가설은 남기되, 이 Frobenius 수식의 학습 진입은 보류한다. 긴 조합의 norm만 보고 이 반대 근거를 무시하지 않는다. 상한 초과를 실제 증폭으로 오해하거나 L을 올려 학습을 정당화하지 않는다. 큰 수량 이득을 유지할 수 있다는 근거는 아직 없다.

## 7. 가설의 구현안을 확정할 때 적용할 비교 기준 — 미실행

기존 원본 Shared15 seed42·52·62의 저장 Validation을 주 대조로 사용한다. 내부 기전 대조와 별개로 RMTPP·S2P2 등 외부 비교군도 같은 대상의 저장 지표로 계속 제시한다. 새 후보가 Shared15보다 좋아져도 외부 비교군 전체 우세가 자동 성립하지 않는다.

원본 RAF·시간/수량 log1p·log MSE·시간 손실 가중치1·공통 head·memory·폭15·optimizer·예산·seed·최초 strict finite 전체 Validation raw RMSE 최소 epoch 선택을 유지한다. 수치는 [기존 원본 계약](../titantpp_history_mlp_shared_raw9_20261020_v1/SCIENCE_SPEC.json)의 common_condition을 그대로 참조한다. 원래 계약의 과거 host 지시를 현재 실행 명령으로 재사용하지 않는다. 동일 초기 tensor와 Runtime 조건을 확인할 수 없으면 순수 구조 인과 비교로 표현하지 않는다. 같은 조건의 새 대조 학습이 필요해지면 사용자가 결정할 별도 범위로 남긴다.

통과 조건은 모두 충족해야 한다. MAE 차이는 candidate−원본 Shared15로 계산한다.

- 급락577행의 MAE가 **세 seed 모두 엄격히 감소**한다. 양의 signed error와 비급락 구간도 보존해 전체 예측 하향 여부를 함께 본다.
- 전체 Validation MAE의3seed 평균이 엄격히 감소하고, 전체 RMSE 평균은 악화하지 않는다.
- q>200의50행 RMSE·MAE3seed 평균이 **각각 원본 Shared15보다 높아지지 않는다**. RMTPP보다 여전히 낮다는 것만으로 이득 보존을 인정하지 않는다. seed별 악화·과소편향도 모두 보고한다.
- 이력1/2/3–4/5–8/9+와 수량 구간의 교차 결과, 지속 고수량·급증 구간, 시간 지표를 보고한다. 사후 최선 구간을 골라 통과 기준으로 바꾸지 않는다.

급락 개선 대신 큰 수량 이득을 잃으면 균형 개선 가설을 기각한다. 제약이 작동하지 않았는데 성능만 달라지면 그 결과를 제안 민감도 기전의 증거로 해석하지 않는다. 이 조건은 탐색적 Validation 기준이며 통계적 유의성·독립 일반화의 증명은 아니다. Test는 이번 설계 범위에 포함하지 않는다.

## 8. 남은 순서

1. **단일 가설의 실용적인 제약식을 결정 — 다음 작업:** 기존 가설을 유지하면서 불필요한 짧은 이력 축소와 큰 수량 손해를 피할 수 있는지 먼저 판단한다. 현재 수식을 학습안으로 채택하지 않으며 다른 gate·loss·L 값의 탐색으로 전환하지 않는다.
2. **후속 구현·검증의 범위를 결정 — 사용자 결정 후:** 수학적 보장만으로 구현과 학습을 자동 정당화하지 않는다. 이 가설을 여기서 보류하는 선택도 남긴다.
3. **고정 조건의 RAF3seed 학습·Validation 비교 — 현재 미확정:** 구현안을 확정하고 검증한 뒤 사용자가 결정할 대상이다. 현재 실행 진입점·실험용 integrity SHA·native 검증 결과는 없다.

기존 5080 추가2seed 실험과5090 작업·회수는 별개로 유지한다. 이번 설계 때문에 기존 학습의 중지·재시작·재평가·실행 순서 변경을 하지 않는다.

근거 파일: SOURCE_BINDINGS.json, OVERLAP_AUDIT.json, INDEPENDENT_DESIGN_REVIEW.md, WEIGHT_NORMS.json·WEIGHT_NORM_ANALYSIS.py, WEIGHT_ADDENDUM_REVIEW.md. 오류 수치의 원본은 기존 RAF 진단의 RESULT.json·DETAILS.json·DATASET_AUDIT.json이다. 앞선 독립 검토의 weight-only 미실행 표현은 당시 상태이며 위 추가분석 전임을 구분한다. 추가 독립 검토는24개 seed×prefix의 곱상한과 s_k 산술을 다시 확인했고, 사용 prefix12개 중3개에서 보수성만 축소를 만드는 반대 근거와 학습 보류 판정에 동의했다. checkpoint 재로드나 모델 검증을 대신한 것은 아니다.

## Taxi: 실행 가능한 형태의 후보는 찾았지만 아직 통과 판정은 아님

현재 `yellow_trip.parquet`의 pickup 날짜 footer는 **2015-01-01 00:00:00~2015-01-31 23:59:59**, 가공 자료는 같은 달의 시간 단위입니다. 이 확인은 날짜 통계만 읽었으며 행·수량·시간간격은 읽지 않았습니다. 날짜 범위가 해당 월이라는 사실은 공식 전체 월 자료와 내용·완전성이 동일하다는 증명은 아닙니다.

공식 [2015 Yellow Taxi 컬럼 정의](https://data.cityofnewyork.us/api/views/2yzn-sicd/columns.json)에서 `pickup_datetime`, `pickup_longitude`, `pickup_latitude`가 확인됐습니다. [공식 데이터셋 메타데이터](https://data.cityofnewyork.us/api/views/2yzn-sicd.json)의 TLC 출처도 확인했습니다. 현재 전처리 코드의 0.02도 격자와 연결할 수 있는 후보입니다. 반면 [2025 TLC 자료 사전](https://www.nyc.gov/assets/tlc/downloads/pdf/data_dictionary_trip_records_yellow.pdf)은 구역 ID를 사용하므로 최신 자료를 기존 격자로 직접 바꿀 수 있다고 가정하지 않습니다.

구체적인 후보는 **2015-02-01 00:00 이상, 2015-03-01 00:00 미만**입니다. 성능을 보고 월을 고르지 않도록 현재 자료 다음 달을 선택했습니다. 2월 레코드를 내려받거나 분석하지 않았습니다. 사용자는 2월의 과거 사용 여부에 **“확인이 필요함”**이라고 답했으므로 `prior_access_status=user_unsure`로 남깁니다. 미사용 확인으로 해석하지 않습니다.

추가로 로컬 `sample_data`·`benchmark_data`·`search_artifacts`의 파일명 39,798개와 실행·출처 계약 251개의 명시된 경로·날짜 메타데이터, 현재 Taxi notebook의 코드 셀을 제한적으로 확인했습니다. 2015년 2월을 명시하는 파일명·계약 필드·코드 일치는 없었습니다. 결과/예측 파일과 notebook 출력은 열지 않았습니다. 일반적인 파일명, 삭제된 파일, 다른 컴퓨터·외부 저장소·과거 사람의 열람은 이 검색으로 확인할 수 없어 **미사용 증거로 승격하지 않습니다**. 범위와 개별 계약 해시는 [taxi_access_search.json](taxi_access_search.json)에 남겼습니다.

실행 전에는 다음을 고정해야 합니다.

- 1월 말까지 선택된 기존 격자 ID를 그대로 사용합니다. 2월의 활동량이나 수량으로 격자를 다시 선택하지 않습니다.
- 현재 코드의 실제 코호트 필터는 전체 1월에서 활동한 시간 칸 수 72 이상입니다. `min_count=100`, `min_coverage=0.999`는 train의 max-order 산출 규칙이며 이 코호트 필터가 아닙니다.
- 시각대·좌표 경계·격자 반올림·vendor 처리·관측된 전체 시간들의 순번과 실제 달력 시간의 대응을 확인합니다. 필드 이름 변경만으로 호환성을 통과시키지 않습니다.
- 1월의 관측 이력을 초기 문맥으로 쓰고, 2월에서도 각 예측 시점까지 공개된 과거만 모든 방법에 동일하게 제공합니다. scaler·어휘·파라미터를 다시 맞추지 않습니다.
- 2월만 사용하면 168시간 비중첩 블록이 네 개뿐입니다. 강한 시간 일반화나 안정적인 신뢰구간을 보장하기 어렵습니다. 필요하면 **결과 접근 전에** 기간·최소 블록 수에 관한 설계를 다시 고정해야 하며, 결과를 본 뒤 유리한 월을 추가하면 안 됩니다.
- 기존 파일·모든 개발 캠페인과의 event 중복, 과거 2월 접근·사용 여부, 실제 소스 이용 조건을 확인한 뒤에만 `PASS`로 올립니다.

입력·시간·사건 정의가 그대로라면 기존 checkpoint로 평가할 수 있으며 MLP를 다시 학습할 필요는 없습니다. 구역 ID나 다른 시간 집계로 바꾸는 경우는 기존 구조 비교를 재사용하는 범위를 벗어납니다.

## Intermittent: 날짜와 생성 계보를 먼저 풀어야 함

원본 경로 `/Users/igwanhyeong/data/demand_engine/data_v2/intermittent.parquet`와 그 상위 `demand_engine` 경로가 현재 로컬에 없습니다. 선택 계열 파일의 **site_cd·oper_part_no 두 열만** 다시 읽어 50개 사업장과 5,000개 계열을 확인했습니다.

파생 event 파일의 `demand_dt` footer는 **2018-01-01~2030-03-18**입니다. 빌드 코드는 원본 날짜를 `%Y%m%d`로 파싱합니다. 2026-10-03 현재보다 미래를 포함하지만, 그것만으로 합성 자료라고 단정할 수 없습니다. 실측 날짜인지, 이동한 날짜인지, 생성 과정이 만든 시간인지 원본 계보로 확인해야 합니다. 따라서 “현재 기간 다음의 신규 실측 자료를 가져오면 된다”는 경로를 지금 확정할 수 없습니다.

현재 빌드 소스는 전체 원본의 양수 사건 수 20 이상으로 적격 계열을 고르고, 전체 사건 수와 계열 전체 길이의 첫 70%에서 계산한 수량 통계로 층화합니다. 이 규칙에는 미래 사건의 존재·개수 정보가 들어갑니다. 새로운 전향적 코호트에서는 전체 기간의 길이나 수량으로 자격을 정하지 말고 **고정된 과거 기준일의 ID·이력**으로 정해야 합니다.

자료 소유자가 원본 SHA·생성 또는 추출 revision·날짜 의미·기존 사업장/부품 ID 대응·사용 권한·별도로 봉인한 코호트를 제공해야 합니다. 생성 자료라면 독립 난수 계열의 생성 실험으로 명시하고, 새로운 실측 자료에서의 일반화라고 쓰지 않습니다. 새 실행을 요청하거나 수행하지 않았습니다.

## Instacart: 공개된 2017 자료의 재구성으로 새 독립 자료를 만들 수 없음

[공식 배포 공지](https://tech.instacart.com/3-million-instacart-orders-open-sourced-d40d29ead6f2)와 [공식 연결 자료 사전](https://gist.github.com/jeremystan/c3b39d947d9b88b3ccff3147dbcf6c6b)은 상대 시간과 30일 상한을 설명합니다. 달력상 “다음 해 자료”를 기존 파일에서 식별할 수 없습니다. 현재 전처리 코드는 prior와 train의 product 행 수로 주문 크기를 만들고, 같은 사용자의 동일한 누적 상대 일자에 있는 주문들을 합칩니다. 따라서 그대로의 단일 주문 수량·물리적 상품 개수라고 넓혀 해석하면 안 됩니다. 당시 frozen 파일을 만든 코드와 현재 notebook의 동일성은 추가 연결 항목입니다.

공식 [약관](https://gist.github.com/jeremystan/582eba13d6ee27ed465c43dc78934700)은 비상업 사용과 제3자 배포 제한을 포함합니다. 현재 권한까지 자동으로 입증하지는 않습니다. [공식 대회 페이지](https://www.kaggle.com/competitions/basket-analysis)는 주최자 요청으로 비활성화됐다고 명시합니다. 이것만으로 모든 과거 연구 이용이 취소됐다고 판단하지도 않습니다. 현재 연구 범위에 적용되는 권한을 별도로 연결해야 합니다.

공식 후속 동종 데이터는 이번 제한된 조사에서 검증하지 못했습니다. [Cornell uchoice-Instacart](https://www.cs.cornell.edu/~arb/data/uchoice-Instacart/)도 2017 자료에서 파생됐으므로 새로운 독립 코호트가 아닙니다. 독립 원본을 확보하더라도 사용자·주문 중복과 상대 시간·합산 정의를 먼저 맞춰야 합니다.

## RAF: 같은 84개월 원본의 새 분할은 독립 후속 자료가 아님

기존 원본 파일의 SHA와 날짜 메타데이터를 다시 확인했습니다. 학습 1996-01~2000-10, validation 2000-11~2001-11, 기존 test 2001-12~2002-12이며 그 이후 월은 없습니다. workbook 행은 열지 않았습니다.

[원 배포 저장소](https://github.com/danieldehaan96/spdf)의 [API 메타데이터](https://api.github.com/repos/danieldehaan96/spdf)는 공개 저장소이지만 `license=null`입니다. 이것은 불법 사용이라는 판정도, 자유 이용 권한이라는 판정도 아닙니다. 기존 로컬 계약의 학술 이용 가능 문구는 저장소 소유자의 명시적인 허가서가 아니므로, 신규 자료의 권한 증거로 승격하지 않습니다.

기존 25개 로컬 launch contract의 validation-only 기록은 재사용할 수 있지만 모든 역사적 머신·노트북·사람의 접근을 증명하지 않습니다. 기존 holdout을 별도 허가로 평가한다면 이 한계를 표시합니다. 독립 확증을 원하면 원본 계보와 권한이 확인된 다른 부품 또는 추가 월 자료가 필요합니다.

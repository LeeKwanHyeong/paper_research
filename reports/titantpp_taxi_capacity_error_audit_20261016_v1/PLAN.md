# Taxi 용량 대조군 오류 분해

## 저장 자료와 비교 가능 범위를 확인한다 — 완료

- 대상은 기존 CNN·이력 적응 CNN·용량 대조군의 seed42/52/62, 고정 선택 checkpoint다.
- 이번 요청은 앞선 Test 평균의 seed 차이를 설명하는 분석이므로, 이미 완료된 Validation/Test 저장 결과를 사용한다. 새 Test 계산·추론·학습은 하지 않는다.
- 해당 평가의 개별 예측 행은 저장되지 않았다(raw_predictions_written=false). 개체·변화 패턴별 행 대응, 개선 사례 수, 상위 오류 사례 목록은 현재 자료로 확인할 수 없다. 앞선 답변에서 이를 바로 비교할 수 있는 듯 설명한 부분은 정정한다.
- 전체·Train 고정 수량 구간별 SSE/AE/부호 오차 합계와 Validation의 이력 길이 구간별 집계는 존재한다. 이것을 별도로 검산한다.

## 같은 대상의 오류 합계를 분해한다 — 진행 중

- 모든 원본 SHA와 평가 대상·정답·입력·선택 checkpoint 연결을 확인한다.
- 수량 구간은 기존 7/686/1562/3449, 이력 길이는 기존 64/128 경계를 유지한다. 수량 구간은 실제 정답에 따른 사후 설명이며 미래 입력 조건으로 사용하지 않는다.
- 과대예측 오차량=(AE+부호 오차 합계)/2, 과소예측 오차량=(AE−부호 오차 합계)/2로 계산한다. 이것은 오류량이며 건수나 같은 행의 이동을 뜻하지 않는다.
- Capacity−CNN, Adaptive−CNN, Capacity−Adaptive를 모든 seed와 구간에서 보고한다. 제곱오차·절대오차 합계의 가산성, 평균 RMSE/MAE 및 표본 표준편차를 확인한다.
- 선택 checkpoint의 Train 개별 평가 예측은 후보에 없고 학습 중 loss는 그 대용이 아니다. Train/Validation 패턴의 일관성을 입증했다고 표현하지 않는다.

## 다음 가설의 근거와 한계를 판단한다 — 다음 작업

- 한 seed의 큰 이득, 구간별 상쇄, 평균 편향과 오차 크기의 차이를 구분한다.
- 실제 수량 구간이나 평균 편향만으로 gate·감쇠·새 head를 정당화하지 않는다. 특정 이력 처리 방식의 결함이나 인과 기전은 별도 근거가 있어야 한다.
- 별도 보고서와 원본 목록을 남기고 Notion에 결론을 누적한다. 기존 CNN·원본·원고·Runtime·자동화는 변경하지 않는다.
- 같은 입력·비교 계약에 의존하므로 이번 분석은 현재 세션에서 직렬로 진행한다.

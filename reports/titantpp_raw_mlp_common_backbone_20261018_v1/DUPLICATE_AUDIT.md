# 원본 MLP 공통 백본 후보의 기능 중복 감사

작성일: 2026-10-18. 상태: **한정된 소스 감사 완료 / 후보의 효과 미검증 / 구현·학습 미실행**.

이번 감사는 기존 코드와 순수 Train·Validation 설계 문서만 읽었다. 예측 행의 새 통계 계산은 부모 분석에서 별도로 수행한다. Test·혼합 성능, 원고, checkpoint tensor를 열지 않았고 추론·학습·SSH·기존 파일 수정은 하지 않았다. JSON에 읽은 주요 소스와 SHA를 기록했다. 프로젝트 architecture-reviewer 설정은 gpt-6-astra/high이지만 실제 로드 모델명은 제공된 도구로 독립 확인하지 못했다.

**확인할 구조 문제 — 완료**

MLP4·MLP16·AllAvailable·CurrentOnly의 추가 보정은 모두 첫 encoder block 이후 64차원 상태를 입력으로 받는다. CurrentOnly도 이미 attention으로 과거 정보가 섞인 현재 위치의 상태다. 다음 질문은 관측된 현재 시간·수량의 초기 임베딩을 후기 백본에서 별도로 읽을 통로가 도움이 되는가다. 출력 오류만으로 현재 정보가 소실됐다고 결론 낼 수는 없다. 원래 Titan block에도 입력을 전달하는 잔차 연결이 존재한다.

**기존 구조와 후보의 차이 — 완료**

| 기존 방식 | 코드에서 확인한 처리 | 후기 현재 관측 재주입과의 차이 | 이번 감사의 실행 상태 확인 범위 |
|---|---|---|---|
| MLP4·16, AllAvailable, CurrentOnly | 첫 block 이후 h1의 현재·직전 쌍 또는 현재 상태를 보정 | 원래 관측 임베딩 e0를 따로 보존해 두 block 뒤로 전달하지 않음 | 구현 확인; 저장 Train·Validation 존재는 기존 순수 분석 문서에 기록됨 |
| MultiLag·LevelHistory·Vdifference | 여러 관측 거리 또는 잠재 상태/투영의 수준·차분 | 입력 정보의 후기 우회 경로가 아닌 잠재 이력 변환 | 구현 확인; 개별 학습 완결성은 이번 감사에서 재검증하지 않음 |
| ActiveBranchNorm·AdaptiveHistory | 활성 분기 수의 분모 변경 또는 관측 변화 기반 QKV 필터 조절 | 보정 집계·필터 가중의 변경 | 구현 확인; ActiveBranchNorm verification에는 완료2·예산종료1·보류6이 기록돼 있어 전부 완료로 표현할 수 없음 |
| CrossFusion·PointwiseFusion | 관측 log1p 시간·수량을 별도 임베딩·cross attention/MLP로 처리해 encoder1 이전에 더함 | 이후 두 encoder를 모두 통과함. 후보는 동일 원관측 임베딩을 두 block 뒤에서 다시 읽음 | 구현 확인; 이번 감사는 성능·종료 receipt를 열지 않음 |
| PostAttentionFFN | 마지막 FFN의 현재/이전 은닉 특징을 비선형 보정 | 후기 위치라는 유사성은 있으나 입력은 이미 문맥화된 은닉 상태 | 구현 확인; 후기 시점별 보정만 추가한다면 단순 변형과 중복될 수 있음 |
| LocalGate | raw 관측 시간·수량 차이로 between-block 보정량을 조절 | raw 정보가 gate 역할이며 현재 임베딩을 후기 벡터로 직접 보충하지 않음 | 구현 확인 |
| Successor·TaskRoutedMemory | 원 관측 특징을 과거 episode의 검색값으로 사용해 후기에 더함 | 과거 관측 검색·집계와 현재 위치 e0의 직접 통로는 구별됨 | 구현 확인; 메모리 변경을 후보에 함께 넣으면 비교 축이 섞임 |
| PairMessage | 첫 block 문맥과 attention 가중으로 pair message 구성 | 처음 임베딩을 우회 전달하지 않음 | 구현 확인 |
| SharedW | 동일 pair를 받는 분기들의 입력 변환 W 공유 | 정보 접근 경로가 아니라 가중치 공유 제약 | 10/17 이미 제안; 검사 범위에서 구현·학습을 찾지 못함 |

검색한 현재 모델 소스에서 SwiGLU 명칭은 찾지 못했다. 이는 모든 동결 source·과거 브랜치에 구현이 없다는 증명이 아니다. 새로운 채널 상호작용을 제안할 경우 원래 pair MLP가 이미64채널을 혼합하고 cross_product·CrossFusion·joint CNN도 존재한다는 점부터 대조해야 한다.

**좁혀볼 단일 축 — 다음 검토**

기존 관측 변환과 input projection을 그대로 써 `e0_i = input_proj(continuous_features(dt_i,q_i))`를 얻고 위치 임베딩이 더해지기 전 값을 보관한다. 원래 두 block과 이력 MLP가 만든 상태를 h2_i라 하면 다음 비교가 가능하다.

- 후보: `z_i = LMM(h2_i + P(e0_i))`
- 용량·위치 대조: `z_i = LMM(h2_i + P(h2_i))`
- 참조: 기존 `z_i = LMM(h2_i)`의 저장 결과

두 새 경로의 P는 같은 `64→r→64 GELU`, bias 유무와 초기화를 동일하게 두고 출력 투영을0으로 초기화하는 구조로 검토할 수 있다. 이때 기존 pair MLP, 공통 input/log1p·손실·head·메모리 모듈은 유지한다. 변경 축은 후기 보정이 읽는 입력의 출처다. 후보는 현재 관측의 별도 통로, 대조는 같은 위치의 문맥화된 상태 추가 변환이다. 순수 선형 `P(e0)`는 관측의 선형 재투영으로 축약되므로 이를 풍부한 관계 추론이라고 부르지 않는다.

두 후보의 명목 파라미터 수는 같아도 e0는2개 입력에서 만들어진 저차원 표현이고 h2는 문맥화된 표현이다. 함수 공간과 gradient 경로의 차이는 의도한 비교에 포함된다. 메모리 모듈을 바꾸지 않아도 입력 h2+P가 달라지면 prototype 검색 배분이 달라질 수 있다. 메모리 효과를 완전히 분리한 비교라고 주장하지 않는다.

**대안 비교와 판단 제한 — 완료**

SharedW는 구현·운영 비용이 작고 기존 분기 구조를 유지하지만 이미 제안된 내용이며 현재의 관측 하락 뒤 과대오류와 연결하는 직접 근거가 약하다. 후기 관측 재주입도 구현·운영·유지 비용이 작으며 동일 P를 써 정보 출처 대조가 가능하다. 다만 기존 residual 연결이 이미 현재 입력을 전달하므로 효과가 없을 수 있고, 관측 하락 뒤 실제 반등이 잦다면 현재값에 더 의존하는 구조가 오히려 악화할 수 있다. 따라서 이 후보는 공통 오류의 원인 확정이나 즉시 학습 권고가 아닌, **부모의 원본 Train·Validation 증거와 합쳐 검증 여부를 결정할 단일 정보 경로 가설**이다.

현재 패턴이 Train에서는 혼재하고 seed42의 Validation에만 공통이라면 그 한계를 명시해야 한다. 실제 미래 정답으로 정의한 낮은 수량 구간은 진단층이며 모델의 gate·입력 조건으로 쓰면 안 된다. 기존 CNN은 이 후보의 실행 대조에 추가하지 않는다.

**남은 확인 — 다음 작업**

1. 관측 이력으로만 정의한 하락 조건의 공통 지지와 seed 예외를 부모 분석에서 검증한다.
2. 해당 조건에 미래 정답 수량을 맞춘 비교의 선택 효과가 있는지 따로 설명한다.
3. 근거가 남으면 기존 MLP 기준폭·r·정확 위치·관측 mask를 먼저 고정해 향후 계약을 검토한다. 이번에는 코드·학습을 실행하지 않는다.

이 감사의 비중복 판정은 명시한 소스 범위에 한정된다. 학계의 독창성이나 저장소 모든 과거 실험의 부재를 증명하지 않는다.

# 과거 test 열람·분석 기록 확인

## 2026-10-03 해석 정정 — 접근 이력과 모델 선택 사용을 구분

**과거 test 평가·열람 사실만으로 현재 평가를 무효로 보거나, 신규 데이터 확보를 논문 투고의 필수 조건·최우선 차단사항으로 제시한 설명은 철회한다.** 이 정정은 아래 접근 증거를 삭제하거나 모든 개발 이력의 독립성을 새로 인증하는 것이 아니라, 확인된 사실보다 강했던 해석을 바로잡는 것이다. 접근 이력에서 독립성·투고 가능성을 판단할 때는 이 절을 우선한다.

- **정상적인 평가 절차:** train으로 학습하고 validation으로 구조·하이퍼파라미터·checkpoint를 선택한 뒤 test로 최종 성능을 보고한다. 이전 논문 초안을 위한 최종 test 평가 자체는 이 절차와 양립한다. 사용자는 이번 대화에서 이러한 절차로 test를 사용했다는 취지를 설명했다. 이는 사용자 설명으로 기록하며, 전체 과거 실행을 새로 감사한 결과와 구분한다.
- **이 보고서가 확인한 범위:** 과거 test 열람·모델 간 지표 비교·답변 기록이 있다. 그러나 아래에도 명시했듯 현재 `titantpp_history_mlp`의 최종 선택에 과거 test가 직접 사용됐다는 인과관계는 확인하지 않았다. 결과표의 순위를 기술한 사실만으로 이후 구조·설정 선택에 그 순위를 사용했다고 단정하지 않는다. 제한된 검색으로 모든 미접근을 입증하지 못했다는 사정도 오염의 증거가 아니다.
- **이번 평가에서 확인된 선택 절차:** [108조건 최종 보고서](../titantpp_legacy_evaluation_20261003_v1/FINAL_REPORT.md)는 최초 최소 validation raw 수량 RMSE epoch의 checkpoint를 고정했으며, 이번 test 평가 과정에서 재학습·train/validation 재적합·test 기반 재선택을 하지 않았다고 기록한다. 이 실행 증거를 현재 평가의 근거로 사용한다.
- **성능과 절차는 별개의 판단:** test에서 일부 비교군보다 불리한 결과가 나온 것은 그대로 보고해야 할 성능 관측이다. 낮은 test 성능만으로 test를 개발에 쓰지 않았다고 증명할 수 없으며, test를 참고했어도 다른 모델보다 낮은 성능이 나올 수 있다. 반대로 좋은 test 성능만으로 test 사용을 의심하지 않는다. 판단 근거는 성능의 높고 낮음이 아니라 실제 선택 절차와 기록이다.
- **현재 논문의 해석:** 기존 test 결과를 과거 접근만으로 무효화하지 않는다. 현재 논의할 문제는 validation과 test의 결과 차이, 데이터별 수량 이득의 범위, 시간 NLL 및 구조 대조 결과가 주장과 맞는지이다. `legacy`/`retrospective reevaluation`은 기존 분할을 다시 평가했다는 이력을 뜻하며, 그 이름만으로 test 기반 개발이나 평가 무효를 뜻하지 않는다. 처음 접근하는 새 자료의 평가라고 소급 표기하지도 않는다.
- **신규 자료와 출처 기록:** 신규 Intermittent·후속 기간·외부 자료는 일반화 근거를 보강하는 추가 경로다. 현재 확인된 접근 이력만으로 이를 의무화하지 않는다. 사용자는 출처 기록은 확보 가능하지만 신규 Intermittent 자료는 확보할 수 없다고 답했다. 추출·가공·날짜 이동·코호트 정의를 문서화하는 재현성 작업은 신규 자료 확보 및 test 선택 사용 여부와 별도로 다룬다.
- **이후 개발의 구분:** 향후 현재 test 결과를 보고 모델·하이퍼파라미터를 선택한다면 그 피드백 사용을 별도 개발 이력으로 남긴다. 그렇게 선택한 새 모델의 동일 test 결과를 선택에 관여하지 않은 평가로 설명하지 않는다. 이는 현재 고정 모델의 기존 평가를 소급 무효화하는 뜻이 아니다.

**정정 반영 — 완료:** 관련 준비·설계·모집단·최종 결과 보고서에 이 절을 연결했다. 과거 증거 JSON, 실행 계약, checkpoint, 성능 수치와 원고는 이번 정정에서 변경하지 않았다. 아래 본문과 다음 작업은 최초 조사 당시 기록이며 현재 실행 상태나 신규 데이터 확보 의무로 읽지 않는다.

## 최초 조사 기록 — 보존

**결론 — 과거 프로젝트 test를 실제로 읽고 비교한 기록을 확인했다.**

앞선 조사는 test 파일 생성과 데이터 계보에 집중했고, Codex 실행·대화 기록까지 확인하기 전에 연구자의 기억을 물었다. 기록 검색을 먼저 했어야 한다. 이번 확인으로 ‘과거 열람 자체가 미확인’이라는 설명을 보완한다. 연구자의 “기억이 불확실함” 답변은 그대로 보존하되, 실제 접근 여부 판단은 발견한 실행 기록을 우선한다.

## 조사 범위와 보존

- 로컬 Codex 기록 중 `session_meta.cwd`가 paper_research를 가리키는 파일892개에서 **2026-09-10 이전** test 관련 읽기 명령 후보90개를 추렸다. 이 수치는 확인된 열람90회가 아니다. 코드 검색·메타데이터 조회도 후보에 들어 있다.
- 명령 시각과 command SHA로 중복을 제거하고, 대표적인 성공 읽기/순위 명령6건과 assistant 설명4건을 원본 행에 대조했다. 모든 사람·도구·기간을 포괄하는 전수 감사는 아니다.
- 과거 도구 출력 문자열은 프로그램이 필드명·숫자 행 존재·종료 상태 확인에 사용했다. 성능 숫자는 모델에 출력하거나 새 증거 파일에 복사하지 않았다. 원래 test CSV/parquet·예측 파일은 이번에 열지 않았다.
- 현재 원고, 과학 코드, 기존 결과, 앞선 평가 결정 원본은 보존한다. 이 보고서가 접근 이력에 관한 후속 근거다.

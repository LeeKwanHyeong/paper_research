# 다음 이력 MLP 가설 — 설계 검토 후보, 학습 미승인

## 판단

**1순위 설계 후보는 같은 총 파라미터를 쓰는 2단 순차 잔차 이력 MLP다.** 기존 폭16의 한 번 보정을 폭8 두 번의 순차 보정으로 바꾸는 가설이다. 현재 저장 결과는 이 구조의 효과나 기존 MLP의 깊이 부족을 입증하지 않는다. 폭만 바꾸는 탐색이 두 데이터셋을 함께 개선하지 못했다는 사실과, Taxi에서 직전 관측 표현을 함께 쓰는 방식의 이득이 남았다는 사실을 바탕으로 **구별 가능한 다음 질문**을 제안한 것이다. 모델 구현·합성 검증·학습은 이번 작업에 포함하지 않았다.

## 유지할 경로와 바꿀 한 가지

원래 경로는 입력 투영 → Titan encoder1 → 이력 MLP 보정 → Titan encoder2 → static Hard-LMM → 기존 시간·수량 head다. 이 중 encoder 사이 이력 MLP의 **병렬 합을 순차 합성으로 바꾸는 효과**만 비교한다. 입력/log1p, 관측창, 현재·직전 표현, 원래 8개 분기의 가용 mask, 고정 /8, 메모리, head, 손실, optimizer, seed, 학습 예산, 선택 규칙을 유지한다. Q/K/V 지역 CNN, GRU, RevIN, 추가 gate·norm·잔차 clipping을 넣지 않는다.

현재 표현을 c, 원래 직전 표현을 p, 원래 분기 가용 여부를 A_i라 하자. 폭8 보정 두 개를 다음처럼 둔다.

R_j(c,p) = (1/8) Σ_i A_i B_{j,i} GELU(W_{j,i}[c;p]), j∈{1,2}.

- 병렬 대조: z_parallel = c + R_1(c,p) + R_2(c,p).
- 순차 후보: c_1 = c + R_1(c,p), z_serial = c_1 + R_2(c_1,p).

두 번째 단계의 p는 **원래 encoder1의 직전 표현**으로 고정한다. p까지 갱신하면 추가 과거 정보가 유입되어 관측 범위 변경이 섞인다. A_i도 원래 입력의 가용 여부를 재사용한다. 이 후보는 시간 순서의 recurrent carry를 새로 만들지 않는다.

각 단계는 8 × (128×8 + 8×64) = 12,288개 가중치, 총24,576개로 기존 폭16의 8 × (128×16 + 16×64)와 같다. bias를 추가하지 않는다. 두 단계 output은 기존과 같은 zero 초기화를 사용한다. 서로 다른 함수 합성과 gradient 경로를 비교하므로 파라미터 수가 같아도 최적화 난도·지연시간까지 같다고 주장하지 않는다.

## 별도의 대조군 학습을 중복하지 않는 이유

폭16의 hidden unit16개를 앞8개와 뒤8개로 분할하면 z_parallel은 원래 폭16과 대수적으로 같다. 따라서 폭8+8 **병렬** 모델을 새 방법론으로 이름 붙이거나 별도 과학 비교군으로 학습할 이유가 없다. 기존 폭16 저장 결과를 기준선으로 유지한다. 추후 구현 단계에서는 같은 weight를 분할한 합성 입력의 수치·gradient 동등성을 확인해야 한다. 이번에는 이 모델 검증을 실행하지 않았다.

순차 모델은 두 번째 GELU의 입력이 첫 단계 출력에 의존한다. 일반적으로 병렬 한 단계 모델과 같은 연산으로 환원되지 않는다. 다만 유사한 함수를 기존 폭16도 근사할 수 있으며 순차 모델이 더 우수하다는 결론은 아니다. 공통 초기 tensor/RNG를 보존하는 fresh-fit 초기화와 분할 weight의 대응은 추후 계약에서 명시해야 한다. 기존 학습 checkpoint warm-start로 바꾸지 않는다.

## 이전 시도와의 중복 감사

| 이전 시도 | 확인한 차이와 이번 결정 |
|---|---|
| MLP 폭4/8/12/16 | 모두 한 번의 비선형 보정이다. 폭 변경 재탐색은 후순위다. |
| current-only, all-available, active-branch normalization | 보정 입력·분기 가용성·나눗셈을 바꾼다. 이번 후보는 모두 원래대로 유지한다. |
| level/change 분리, cross-product | 입력 분해나 두 상태의 곱을 바꿨다. 이번에는 같은 concat 입력과 GELU를 유지한다. |
| recent-four mean, attention/routing, MultiLag | 참조 이력이나 집계 방식을 바꿨다. 이번에는 동일 직전 표현만 재사용한다. |
| post-block MLP | 보정 위치 이동이다. 이번에는 기존 encoder 사이 위치를 유지한다. |
| conditional/constant gate, MemoryFiLM, residual cap | 보정량·조건화를 바꿨다. 이번에는 별도 배율 탐색을 하지 않는다. |
| 비선형 QKV·Q/V 위치·Vdifference·QKOnly·QOnly/KOnly, AdaptiveHistory CNN | attention의 필터/이력 처리를 바꿨다. 이번에는 이 CNN 계열을 가져오지 않는다. |
| post-attention FFN current/temporal | encoder2 FFN 내부의 채널별3tap 비선형 잔차다. 이번은 encoder 사이의 128→8→64 교차채널 pair MLP 두 번 합성이다. 같은 비선형 처리라는 큰 범주는 겹치므로 완전히 새로운 원리라고 부르지 않는다. |
| CurrentStateGRU의 two-step | 같은 현재 상태를 두 번 넣는 gated recurrent 연산이다. 이번에는 GRU·반복 상태·가중치 공유가 없고 원래 pair MLP의 순차 합성만 비교한다. |
| 시간·수량 shared/private·task-routed memory | 과거 검토·부정적 결과가 있다. 수량/시간 지표의 상충만으로 간섭을 확정하거나 이 경로를 재추천하지 않는다. |

코드·계약·보고서 검색 범위에서 이 정확한 **원래 가용 mask와 /8을 유지한 pair MLP 폭8+8 순차 대 폭16 병렬** 비교는 확인하지 못했다. 저장소의 모든 미기록 실험이 없다고 증명한 것은 아니며, 논문 수준의 독창성 감사도 아니다.

## 판정 기준과 반증 가능성

**기전 가설:** 같은 참조 정보·총 용량에서, 첫 보정을 반영한 표현을 두 번째 단계가 다시 처리하는 방식이 한 번의 넓은 보정보다 두 데이터셋에 공통으로 유용한 표현을 학습하는가?

- 기존 폭16 대비 Validation 전체 raw RMSE와 MAE를 함께 낮추는지를 주 비교로 둔다. 저장 폭4는 RAF의 강한 보조 비교이며 사후 기준선 교체는 하지 않는다.
- RAF에서 큰수량39/50개만의 개선이 나머지 구간의 오차 증가를 가리는지 별도 분해한다. 큰수량 여부는 실제 target 수량에 따른 **사후 진단**이며 모델이 예측 전에 아는 gate 조건으로 사용하지 않는다.
- Taxi에서는 seed42 하나의 개선만으로 평균 우위를 만들지 않는지 seed별 차이·표본SD와 함께 확인한다. 3seed는 통계 유의성을 보장하지 않는다.
- 전체·큰수량 TimeNLL과 수량 오류의 악화를 모두 보존한다. 수량 개선을 공동 예측 전체 개선이라고 표현하지 않는다.
- 관측창·총 용량이 같은데 결과가 비슷하거나 나쁘면 “깊이 부족이 병목”이라는 설명의 근거가 약해진다. 그때 깊이3·4, 여러 배율을 자동 탐색하지 않는다.
- 최종 성능 목표인 기존 CNN 및 같은 대상 외부 지표별 최우수와 Validation/Test의 RMSE·MAE 비교는 별도로 유지한다. 기존 CNN·외부 모델은 저장 결과만 사용한다.
- 다음 실행을 선택한다면 Test는 Validation 선택 checkpoint를 고정한 뒤 승인된 범위에서만 평가한다. 이미 Test를 참고해 고안한 후보이므로 새 독립 일반화 평가라고 주장하지 않는다.

현재는 **새 학습 결정 대기**다. 충분한 기전 근거가 이미 확보됐다는 판정이 아니라, 기존 탐색과 구별되는 제한된 설계 질문을 준비한 상태다. 추가 구조 후보를 동시에 쌓지 않는다.

## 문헌과 기여 범위

잔차 블록의 순차 합성과 identity 경로는 이미 확립된 설계다. [Identity Mappings in Deep Residual Networks](https://arxiv.org/abs/1603.05027)는 잔차 경로의 신호 전달을 연구한다. [ResMLP](https://arxiv.org/abs/2105.03404)는 잔차 MLP 구조를 다룬다. 두 논문은 설계상의 참고이며, Taxi/RAF 성능 개선이나 현재 오류 원인의 근거가 아니다. 이 후보가 성공하더라도 “MLP를 깊게 쌓았다” 자체를 새 기여로 주장할 수 없다. 동일 정보·용량에서의 효과와 적용 범위를 보여줘야 한다.

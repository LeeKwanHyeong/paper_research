### 2. 기존 Titans에서 계승한 부분과 우리가 입증할 부분

[원본 Titans](https://arxiv.org/abs/2501.00663)는 test-time neural memory를 포함한 장기 기억 구조를 다룬다. 현재 실험 구현과 원본 전체 알고리즘을 동일시하면 안 된다. “원본 Titans의 무거운 연산을 덜어내 더 좋은 모델을 만들었다”를 직접 주장하려면, 무엇을 제거·대체했는지 대응표와 원본 또는 동등 기능 구현에 대한 정확도·비용 비교가 필요하다.

현재는 **Titans에서 영감을 받은 표현 구조를 사건 수량 예측에 맞게 구성했다**는 출발점이 안전하다. 직접 압축 비교를 하지 않으면 원본 Titans 대비 가속 배수나 정확도 우위를 기여로 쓰지 않는다.

**현재 코드에서 명확히 설명할 수 있는 설계 [L4]**
- B도 인과적 사건 이력을 사용하는 backbone이다. B를 “이력이 없는 모델”로 설명하지 않는다.
- History MLP는 backbone 내부의 현재·직전 hidden state를 받아 보정량을 만드는 모듈이다. 기존 외부 비교군에 독립적인 MLP 예측기를 하나 추가한 실험과는 다르다.
- 보정은 두 encoder 단계 사이에서 작동한다. 저차원 투영과 출력의 영 초기화는 공통 초기 예측을 유지하면서 추가 경로를 학습하게 한다.
- 여덟 분기는 현재 구현상 서로 다른 여덟 시간 지연을 읽는 구조가 아니다. **동일한 인접 이력에 서로 다른 이력 길이별 활성 조건을 적용**한다. 이를 검증 없이 다중 시간척도 기억이라고 부르지 않는다.
- Full과 MLP는 Taxi·Intermittent 기준 전체 파라미터가 각각 96,003개로 같다. 따라서 **MLP로 바꿨다는 이유만으로 파라미터 경량화가 증명되지는 않는다.** 실제 연산·메모리·지연을 측정해야 한다.

**현재 승인된 MLP Gate의 해석**
관측된 이력에서 얻은 보정량을 r, backbone 표현을 h라고 하면 출력은 개념적으로 다음과 같다.

$$
\tilde h_i = h_i + g_i r_i
$$

plain MLP는 g=1, 상수 계수는 학습 가능한 하나의 값, 조건부 Gate는 관측 이력 특징의 함수다. 현재 Gate는 2·sigmoid 형태로 초기값이 1이며, 보정 출력 전체의 강도를 조절한다. 조건부 입력은 관측 수량 변화, 최근 변화의 방향 지속성, 사건 간격, 이력 길이이며 미래 정답을 사용하지 않는다. **Gate 자체가 새로운 발명이라는 주장을 앞세우기보다 이 과제에서 어떤 과보정·부족 보정을 줄이는지 입증한다.**

**독창성 점검의 완료 조건:** 시간·수량 입력, 저차원 잔차 모듈, sigmoid Gate는 각각 이미 널리 쓰이는 설계 도구다. 이 요소의 조합만으로 독창성이 확보됐다고 쓰지 않는다. 가장 가까운 선행방법과 입력 정보·보정 위치·연산식·학습 방식·복잡도를 나란히 놓고, 우리의 선택이 해결하는 구체적 문제와 대조 실험의 결과를 연결한다. 실질적 설계 차이가 없다면 새로운 범용 backbone 주장보다 과제 특화 구성과 실증 기여로 범위를 좁힌다.

### 5. 추가 비교군은 이렇게 구성한다

**2026-09-29 데이터 적합성 확인 후 수정:** 현재 동결 데이터는 등간격 달력 시계열이 아니라 사건 목록이다. PatchTST·PatchMixer·DLinear를 곧바로 우선 주 비교군으로 올린 기존 제안은 수정한다. **기존 RMTPP·THP·NHP·SAHP를 유지하고, 추가 주 비교 후보는 불규칙 사건을 다루는 S2P2·AttNHP부터 검토한다.** 이들도 현재의 수량 target·시간 관측 단위·공통 head에 맞는지 검증해야 하며, 공식 구현의 존재만으로 적용 완료가 아니다. 패치·선형 시계열 모델은 별도 변환 타당성 검토를 통과할 때만 보조 비교로 제안한다.

추가로 **직전 수량 유지, 과거 이력만 사용한 평균 예측**을 단순 기준선으로 둔다. 이들은 복잡한 모델의 실질적인 이득을 확인하는 기준이며 새 아키텍처 후보가 아니다.

우선순위는 **같은 다음 사건 수량 과제에 맞는 비교**다. PatchTST·PatchMixer와 비교해야만 backbone 기여가 성립하는 것은 아니다. 별도 사건 순서 변형을 추가한다면 변형 모델임을 표기하고, 원래 등간격 장기 예측 모델 대비 우월성으로 확대하지 않는다. 이 목록만으로 모든 최신 방법을 망라했다고 주장하지 않으며, 투고 직전에 관련 문헌을 갱신한다.

### 6. “동일 조건”은 두 종류의 비교로 나누어 명시한다

**A. Backbone 효과를 분리하는 통제 비교**
- 같은 데이터 split, 관측 정보, target, 평가 순서, 공통 head·loss와 선택 기준을 사용한다.
- 현재 B·Full·MLP와 외부 네 모델 결과가 이 패널의 출발점이다.
- architecture별 수정 내역을 공개하고, 공통 head로 바꾼 모델은 “공통 head에 맞춘 backbone 비교”로 표기한다.
- 같은 seed가 서로 다른 모델의 모든 tensor를 동일하게 만든다는 뜻은 아니다. 대응되는 공통 부분과 초기 예측의 동일성을 확인한다.

**B. 강한 예측 방법과 비교하는 구조 보존 평가**
- 각 모델의 핵심 구조·decoder를 가능한 보존하고, 같은 관측 정보·데이터·목표에서 평가한다.
- 같은 학습률 하나를 모든 모델에 고정하는 것만으로 최상의 공정성을 주장하지 않는다. 모델별 공식 권장 범위에서 **사전에 정한 동일 탐색 예산**과 validation 선택 규칙을 적용하는 별도 계약을 제안한다.
- 원래 count head가 없는 TPP에는 동일한 수량 head를 붙이는 통제 비교가 필요하다. 원래 시간 head를 살리는 평가에서는 시간 likelihood·손실의 차이를 밝히고 A와 별도 표로 낸다.
- PatchMixer의 dual head, DLinear의 선형 예측 경로 등을 제거하면 원 방법의 평가가 아닌 변형 평가가 된다. 제거 범위와 명칭을 표에 표시한다.
- 시간 NLL은 같은 관측 단위와 분포 정의에서 비교한다. 연속시간 밀도와 시간 구간의 확률질량, 잘림·상한 처리 등이 다르면 값을 같은 순위표에 직접 섞지 않는다.
- 새 튜닝 계약의 결과와 기존 고정 설정 결과를 섞어 같은 조건인 것처럼 비교하지 않는다. 현재 진행 중 실험의 설정은 유지한다.

**현재 데이터에서 패치 모델을 바로 쓸 수 없는 이유 — 확인 완료**

확인 대상은 동결 parquet의 schema와 train 행이며 held-out 행·예측 성능은 읽지 않았다. 파일은 `oper_part_no`(계열), `seq`(시간 좌표), `delta_t`(사건 간격), `demand_qty`(사건 수량)를 가진 긴 형태의 사건 테이블이다. 긴 형태나 parquet 저장 형식 자체가 장애는 아니다. **0 수량을 포함한 모든 달력 구간이 보존된 등간격 시계열인가**가 핵심이다.

- **Intermittent:** 전처리 `build_positive_events`에서 `order_qty > 0`만 남긴다. 실제 train 예시의 주 인덱스는 1, 6, 11, 16…처럼 건너뛴다. row를 한 주씩으로 읽으면 시간 의미가 바뀐다.
- **Taxi:** 승차가 있는 시간만 남긴다. 일부 구간이 연속해도 전체 격자의 모든 시간·0 수량을 포함한 테이블이라는 뜻은 아니다.
- **Instacart:** 관측 활동일의 사건 목록이며 기록 간격 상한도 있다. 현재 파일만으로 정확한 일별 달력 수요가 모두 복원된다고 가정할 수 없다.

가능한 경로는 둘이며, 어느 쪽도 단순 파일 포맷 변환이 아니다.
1. **사건 순서로 변형:** 최근 L개 사건의 수량·관측 간격을 고정 길이 입력으로 만들고 다음 사건 수량을 예측한다. 이 경우 등간격 시간 패치는 “연속된 사건 묶음”이 된다. 가변 길이·padding·정규화·간격 사용을 검증한 **사건 순서용 변형 모델**이며 보조 비교 후보로만 둔다. PatchTST는 채널 독립 설계이므로 간격을 별도 열에 추가하는 것만으로 수량 예측에 그 간격이 반영된다고 가정하면 안 된다.
2. **달력 시간축으로 재구성:** 원본과 관측 범위를 확인하고 무사건과 미관측을 구분해야 한다. 빈 구간에 0을 채워 다음 주·시간의 수량을 평가하면 현재의 “다음 발생 사건 수량”과 다른 과제다. 이를 연구하려면 새 데이터·target·split·모델 출력·평가 계약이 필요하다. 현재 결과표에 같은 실험으로 합치지 않는다.

따라서 아래 항목은 **즉시 구현할 계약이 아니라, 보류된 보조 비교의 타당성 심사 기준**이다. 데이터 재구성·새 adapter·새 실험은 수행하지 않았다. 근거: 내부 데이터 특성 분석 [L5], `paper/scripts/build_intermittent_frozen_subset.py`의 `build_positive_events`, [PatchTST 공식 입력 로더](https://github.com/yuqinie98/PatchTST/blob/main/PatchTST_supervised/data_provider/data_loader.py), [PatchTST 설계](https://github.com/yuqinie98/PatchTST), [PatchMixer 공식 모델](https://github.com/Zeying-Gong/PatchMixer/blob/main/models/PatchMixer.py).

**보조 비교를 다시 검토할 경우의 입력 심사 기준**
1. 다음 **관측 사건**의 수량을 예측하는 동일 과제를 유지한다. 무사건 구간을 임의로 0 수요로 넣거나 정규 시계열로 바꿔 다른 문제를 만들지 않는다.
2. 관측된 수량·사건 간격과 허용된 공변량을 동일하게 제공한다. 정규화·스케일 통계는 train에서만 계산한다.
3. 같은 시점에서 같은 과거 prefix 또는 사전에 정한 공통 history cap을 사용한다. 입력 접근 가능 범위를 모델별로 다르게 숨기지 않는다.
4. 짧은 이력은 실제 padding mask로 처리한다. Instacart에서 큰 patch만 강제하지 않고 patch 1·2·4 등의 가능 여부를 사전 검토한다. padding을 실제 사건으로 세지 않는다.
5. 관측된 prefix 내부를 함께 읽는 것은 허용되지만, 각 예측 시점 이후 사건을 읽으면 누출이다. 전체 시퀀스의 여러 위치를 한 번에 학습하는 구현은 causal mask 또는 정확한 prefix 생성이 필요하다.
6. prefix 변환으로 학습 예제 수·노출 횟수·비용이 달라지면 기록한다. 원래 비교군의 공식 benchmark 점수를 가져오는 대신 같은 데이터에서 평가한다.

### 7. 성능·효율·한계에 대한 판정 규칙

**성능과 독립 검증**
- 선택 기준은 기존 **strict 최초 validation raw 수량 RMSE**로 유지한다. 동일 selected checkpoint의 MAE·RMSE를 함께 주 지표로 보고한다. last checkpoint는 별도 구분한다.
- MAE와 RMSE가 엇갈리면 하나만 강조하지 않고 평균 오차와 큰 오차의 차이로 해석한다. 시간 NLL과 장·단기 이력, 수량 규모별 반례도 함께 보존한다.
- 3seed 평균·표본표준편차와 paired seed 차이를 제시한다. 세 번 모두 이겼다는 사실을 곧바로 유의성으로 바꾸지 않는다.
- 독립 평가를 계획할 때 대표 모델·비교군·변환·지표·실패 처리·통계 절차를 먼저 동결한다. 이후 별도 승인된 held-out 평가를 한 번 수행하는 방향으로 설계한다. 현재 페이지 작성 중 held-out 결과는 열람하지 않는다.
- 불확실성 평가는 사건 행을 독립 표본으로 가정하기보다 사용자·품목·격자 등 계열 단위 의존성을 고려한다. seed 변동과 계열 표본 변동을 구분하고, 세 seed를 대량의 독립 표본으로 부풀리지 않는다.
- MAE·RMSE의 개선 폭과 신뢰구간을 보고한다. 동등성 주장은 사전에 정한 실용적 허용 차이와 별도 검증 없이는 사용하지 않는다.

**경량화·효율**
- 동일 GPU, 동일 precision, 동시 학습이 없는 조건에서 warm-up 후 반복 측정한다.
- batch 1 추론 지연, 실제 평가 batch의 처리량, batch 128 학습 step 시간, 최대 메모리, 파라미터와 가능하면 FLOPs를 구분한다.
- 데이터 로딩을 포함한 전체 시간과 연산 자체 시간을 분리한다. early stopping이 일찍 끝난 fit의 총시간만으로 아키텍처가 더 빠르다고 판단하지 않는다.
- 현재 5090 병렬·복구 작업의 시간은 그대로 보존하고, 단독 실행 속도 비교값으로 전환하거나 겹친 시간을 추정해 빼지 않는다.
- 원본 Titans의 test-time memory 비용을 줄였다는 주장은 직접 대응 실험이 있을 때만 사용한다.

**Instacart와 적용 범위 [L5]**
train 분석에서 실제 입력 이력 중앙값은 5개이며, 사용자별 평균을 제거한 인접 log 수량 상관은 0.037이다. 짧은 이력과 약한 인접 관계가 추가 보정의 이득을 제한한다는 **가설**을 세울 수 있지만, 이 값으로 비선형 예측 정보의 부재나 성능 차이의 원인을 증명할 수는 없다.

데이터의 수량 의미도 구분한다. Taxi는 격자별 활성 시간의 승차 수, Intermittent는 양수 주문 수량 사건, Instacart는 같은 사용자의 기록된 같은 날 상품 행을 합친 수량 대용값이다. Instacart의 기록 간격 상한과 이러한 관측 단위를 논문에 명시한다. validation을 보고 만든 구간 설명은 탐색 분석으로 표시하고, 확증 분석의 구간은 독립 평가 전에 고정한다.

### 8. Gate 결과에 따라 논문이 어떻게 달라지는가

**Full Gate의 성공은 MLP Gate 검증의 동기이고, 성공 보장은 아니다.** Gate가 이기지 않아도 연구 전체가 무효가 되는 것은 아니다. 다만 이력 MLP가 유용한 이유와 강한 외부 모델 대비 가치가 남는지는 별도로 입증해야 한다.

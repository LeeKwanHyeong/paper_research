**1. 모든 실험의 종료 증거와 원본을 한 목록으로 확정한다 — 다음 작업 / 이력 보정 종료 후**

- RAF seed42의 full/current_only는 물리 A100 이관을 포함한다. 부모의 disabled 결과와 무중단 동일 GPU 대조라고 쓰지 않는다. RTX로 넘긴 미시작 조건은 A100 큐에서 제외됐는지 확인해 중복 실행을 막는다.
- A100 원본 검증 뒤 전용 Pod와 volume 정리 증거를 확인한다. 새 실험이나 공용 Runtime 변경으로 범위를 넓히지 않는다.
- 완료 조건은 Instacart 9개와 이력 보정 27개의 과학 실행·원본·종료 상태를 한 번씩 추적할 수 있고, 누락이나 미확정이 명시된 상태다.

**2. 같은 선택 epoch의 수량·시간 결과로 보정 기여를 판정한다 — 다음 작업 / 원본 검증 후**

- 각 fit의 full Validation 전체 raw 수량 RMSE에서 최초 strict finite 최소값을 기록한 checkpoint 하나를 사용한다. 그 동일 epoch에서 전체와 큰 수량의 RMSE·MAE·TimeNLL 여섯 지표를 모은다. 시간이나 큰 수량에 유리한 다른 epoch를 따로 고르지 않는다.
- 데이터·seed별 full과 두 대조군의 절대 차이와 변화율, 3seed 평균과 표본 SD를 기록한다. Instacart는 세 구조의 같은 여섯 지표를 별도 표로 정리한다. Instacart 구조 비교를 보정 경로의 효과를 입증한 결과로 해석하지 않는다.
- 기존 Q1 기준을 유지한다. 같은 두 개 이상 core 데이터셋 각각의 모든 3seed에서 full의 전체 수량 RMSE가 보정 제거와 현재 상태 전용 모두보다 엄격히 낮을 때 개발 단계 지지로 판정한다. 통과하지 않으면 미지지 또는 조건부 관찰을 그대로 기록하고 성공 기준을 바꾸지 않는다.
- 큰 수량 오차와 TimeNLL 손해를 수량 개선 옆에 함께 적는다. TimeNLL 차이를 이벤트 시각 오차의 분·시간 차이로 바꾸거나, 미리 정한 효용 근거 없이 시간 손해가 허용된다고 주장하지 않는다.
- 동일 데이터·seed의 세 대조군은 같은 GPU·Runtime에서 비교했는지 표시한다. RAF42 이관 예외는 별도 표식과 해석 한계를 붙인다. 학습 시간은 물리 GPU 구간별로 보고하며 A100 동시 실행 속도를 구조 효율로 해석하지 않는다.
- full/current_only의 활성 보정 파라미터는 같지만 계산 경로·깊이·활성화가 다르다는 한계를 유지한다. 결과만으로 직전 상태 하나가 모든 개선의 원인이라고 결론내리지 않는다.
- 완료 조건은 Q1 판정, 손해 사례, GPU/Runtime 예외를 포함한 최종 Validation 보고가 원본까지 추적되는 것이다. 통계 유의성·참신성·외부 우월성·독립 Test 성능을 이 판정으로 대체하지 않는다.

**3. CNN+GRU54 중심의 Results와 실제 실험 설명을 갱신한다 — 다음 작업 / 판정 확정 후**

- 대상은 현재 `main.tex`와 같은 초안 디렉토리의 수치 출처 문서다. 본문 순서는 대표 CNN+GRU54와 외부 비교군의 성능 위치 → CNN+GRU54 보정 대조 → Instacart 구조 비교를 기본으로 잡는다. 과거 MLP4·MLP8 결과는 개발 동기와 부록 근거로 남긴다.
- 완료된 외부 비교 표와 신규 보정 표는 서로 다른 학습 campaign임을 유지한다. 신규 full 결과를 과거 외부 비교 표의 CNN+GRU54 행에 임의로 교체하거나, 같은 seed라는 이유로 초기화와 Runtime이 같았다고 쓰지 않는다.
- 보정 Results에는 full·보정 제거·현재 상태 전용의 결과와 Q1 판정, 큰 수량·시간 손해를 넣는다. Instacart는 MLP8·MLP12·CNN+GRU54의 완료 3seed 결과로 갱신하고, 기존 단일 완료 관측을 최종 구조 순위의 근거로 사용하지 않는다.
- Experimental Design의 과거 RTX 전용 배정과 63개 자동 진행 설명을 실제 A100/RTX 분담·동시 실행·재사용·재개 내역에 맞춘다. scientific 설정과 운영 복구를 구분하고 RAF42 이관 한계를 기록한다.

- 완료 조건은 핵심 주장마다 직접 대응하는 CNN+GRU54 결과와 출처가 있고, 완료된 Instacart를 진행 중이라고 적은 문장과 미검증 보정 성과를 단정한 문장이 없는 것이다.

**4. 검색 질문을 논문에 남길지 결과를 보고 결정한다 — 다음 작업 / 보정 중심 원고 반영 후**

- 검색은 보조 질문이다. 보정 결과를 설명하는 데 matched mean·weighted·fixed·generic512 비교가 필요한지, 독립적인 주장을 추가할 수 있는지 검토한다. 기대와 다른 보정 결과를 검색 성과가 만회할 것이라고 전제하지 않는다.
- 검색 질문을 남긴다면 같은 데이터·seed·GPU·Runtime의 공통 mean 기준선과 검색 대조, 학습 예산, T64/T256 비용 검사를 구체적으로 확정한다. A100 full 결과를 RTX의 동일 GPU mean 기준선으로 혼합하지 않는다. 추가 학습 수는 재사용 가능 증거를 확인한 뒤 확정하며 여기서 자동으로 27개나 36개를 시작하지 않는다.
- 검색 규칙 네 가지는 모두 정적 prototype을 쓰므로 이 대조로 prototype 유무의 효과를 입증하지 않는다. fixed의 분리 정규화는 연결 dot product 표현과 대수적 동등성을 가지며, 새로운 메모리 원리의 발명으로 설명하지 않는다.
- 유지할 경우 기존 Q2와 양 길이 비용 기준을 바꾸지 않는다. mean·weighted·generic512 각각에 대한 수량 개선과 시간·큰 수량 손해, 추론·학습 step·peak 비용을 함께 보존한다.
- 검색을 이번 논문에서 제외한다면 검증되지 않은 추가 이득을 contribution과 결론에서 제거하고, 필요한 구조 설명과 과거 탐색 관찰의 한계만 남긴다. Results의 “under evaluation” 문장을 완료 결과처럼 채우지 않는다.
- 완료 조건은 검색 질문의 포함/제외 결정과 그 이유가 명시되고, 필요한 경우 후속 자원·비교 계약이 검토 가능한 상태다. 자원이나 평가 범위를 확대하는 실행은 해당 범위의 승인을 확인한 후 진행한다.

**5. 새 독립 평가의 가능성과 평가 계약을 먼저 준비한다 — 다음 작업 / 주장 범위 확정 후; 실행은 별도 승인 필요**

- 아직 성과를 보지 않은 기간이나 데이터가 실제로 남아 있는지 확인한다. 이미 개발 중 관찰한 기존 Test를 새 독립 평가로 이름만 바꾸지 않는다.
- 대표 구조, 비교군, checkpoint 선택, 미노출 데이터 접근 시점, 전체·큰 수량·시간 지표와 평가 절차를 결과를 보기 전에 고정한다. 확보가 어렵다면 원고에서 Validation 개발 증거라는 한계를 유지한다.
- CPU binary 재추론 감사는 보존 checkpoint와 frozen source가 저장 지표를 재현하는지 확인하는 별도 작업으로 설계한다. 현재 코드의 기본값을 과거 frozen 실행의 재현으로 취급하지 않는다.
- 완료 조건은 데이터 확보 가능성, 잠금 범위, 실행 대상과 필요한 승인이 분리된 평가 계획이다. 이 문서 작성이나 기존 학습 승인을 Test 열람·독립 평가 실행 승인으로 확대하지 않는다.

**7. 컴파일과 제출 전 점검을 마친다 — 다음 작업 / 본문·평가 범위 확정 후**

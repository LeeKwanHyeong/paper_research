### 2.1 실제 구조

근거는 [현재 모델 코드](/Users/igwanhyeong/PycharmProjects/paper_research/models/TPPs/CountAwareTitanMultiLagDetail.py), [공통 모델·head](/Users/igwanhyeong/PycharmProjects/paper_research/models/TPPs/CountAwareTPP.py), [동결 replication 계약](/Users/igwanhyeong/PycharmProjects/paper_research/paper/contracts/local_detail_benchmark_replication_v1.json), [복구 계약](/Users/igwanhyeong/PycharmProjects/paper_research/paper/contracts/local_detail_instacart_remaining_recovery_v1.json)이다. 두 모델 파일의 현재 SHA는 두 계약에 기록된 SHA와 일치한다. 이는 해당 파일의 일치 확인이며, 모든 Runtime을 다시 검증하거나 학습을 재현한 것은 아니다.

- 두 인코더 블록 사이에 이력 보완 잔차를 삽입한다. 입력은 첫 블록의 은닉 상태이므로 이미 과거 문맥을 포함한다.
- 주 모델의 **여덟 분기 모두 직전 관측 사건 하나를 참조**한다. `[1,2,4,8,16,32,64,128]`은 이력이 얼마나 쌓였을 때 각 분기를 켜는지 정하는 기준이다. 주 모델의 실제 참조 거리는 `[1,1,1,1,1,1,1,1]`이다.
- 관측 수가 해당 기준보다 클 때 분기가 활성화된다. padding은 관측 수에 포함하지 않고, 관측에서 제외된 유효 행은 이력 사용 가능 구간을 끊는다.
- 각 분기는 bias 없는 수준 투영·변화 투영·출력 투영을 사용한다. rank는 4, hidden dimension은 64이며 출력 투영은 0으로 초기화한다. 여덟 분기 합을 항상 8로 나눈다.
- 두 번째 블록 뒤의 static Hard-LMM은 64개 학습 가능한 prototype 중 top-4를 산술평균해 검색한다. persistent memory 16개와 구분해야 한다. 이 구조는 추론 때 쓰기를 수행하는 Titans의 온라인 메모리가 아니다.
- 수량과 시간은 같은 최종 상태를 사용한다. 수량은 log-MSE, 시간은 기록된 양의 정수 간격에 맞춘 lognormal 기반 head다. 수량 자체의 완전한 확률분포를 학습하는 모델이라고 표현하지 않는다.

현재 관측 상태를 \(h_j\), 직전 관측 상태를 \(h_{j^-}\), 분기 활성 여부를 \(a_{jb}\)라 하면 코드의 잔차는 다음과 같다.

\[
\ell_j=(h_j+h_{j^-})/2,\qquad \delta_j=h_j-h_{j^-},
\]
\[
r_j=\frac{1}{8}\sum_{b=1}^{8}a_{jb}U_b\left[\operatorname{GELU}(L_b\ell_j)+\operatorname{GELU}(D_b\delta_j)\right].
\]

**두 GELU를 따로 계산한다.** `GELU(Lℓ + Dδ)`나 원시 수량의 추세·계절성 분해로 설명하면 현재 구현과 다르다. 코드에 함께 존재하는 `multilag` 변형을 주 모델로 혼동하지 않는다.

### 2.2 신규성 판단에 중요한 수학적 한계

수준·변화 변환은 가역적이다. \(h_j=\ell_j+\delta_j/2\), \(h_{j^-}=\ell_j-\delta_j/2\)이므로 **새 관측 정보를 추가하지 않는다**. 아래 설명은 코드에서 도출한 분석이며, 새 성능 실험 결과가 아니다.

한 분기는 입력 \(z=[h_j;h_{j^-}]\)에 대해

\[
W_b=\begin{bmatrix}L_b/2&L_b/2\\D_b&-D_b\end{bmatrix},
\qquad V_b=[U_b\ U_b],\qquad g_b(z)=V_b\operatorname{GELU}(W_bz)
\]

로 다시 쓸 수 있다. 즉, **입력 가중치의 대칭·반대칭과 출력 공유를 제약한 두 층 MLP**로 표현 가능하다. “일반 MLP가 표현할 수 없는 새로운 연산”은 적절한 주장이 아니다. 차별성 후보는 이 제약, 블록 사이 삽입, 초기화 및 이력에 따른 활성 방식의 조합이 주는 효율이다.

분기당 자유 파라미터는 \(3dr\), 전체 추가량은 \(8\times3\times64\times4=6,144\)개다. 인접 상태를 이어 붙인 일반 MLP도 폭 \(r=4\)이면 분기당 \(2dr+rd=3dr\)로 맞출 수 있다. 다만 제안 구조는 분기당 GELU 입력이 \(2r\)개여서 **파라미터 수를 맞춰도 활성 폭과 연산량까지 같지는 않다**. 폭 \(2r\)의 비제약 MLP는 표현 관계를 확인하는 보조 대조군이며 파라미터가 두 배다.

### 내부 비교의 의미를 미리 명확히 한다

| ID | 설계상 비교 조건 | 답하는 질문 / 공정성 주의 |
| --- | --- | --- |
| Full | 현재 이력 보완 TitanTPP | 주 모델. 이미 완료된 결과를 현재 기준선으로 유지한다. |
| B | 이력 보완이 없는 기존 TitanTPP | 보완 구조 추가의 전체 효과. 파라미터 수가 작으므로 이것만으로 구조의 독립 효과는 증명 불가. |
| A1 | `[h현재; h직전]` 입력의 bias 없는 일반 2층 MLP, 분기당 폭 4 | 총 +6,144개로 Full과 일치. 여덟 분기·활성 mask·삽입 위치·분모·0 출력 초기화 유지. 파라미터 일치와 연산량 일치를 구분. 가장 먼저 검증할 대조군. |

| A3 | 변화 투영만 남긴 rank 4 구조 | 수준 경로 제거 효과. A2와 같은 용량 주의. 활성 파라미터를 맞추는 rank 6 보조 조건은 폭도 바뀌므로 계약 단계에서 별도로 판단. 사용하지 않는 가짜 파라미터로 수를 맞추지 않음. |
| A4 | Full에서 static Hard-LMM 검색만 제거 | static 검색의 필요성. persistent memory까지 제거한 “모든 메모리 제거”로 표현하지 않음. 현재 코드가 static LMM을 요구하므로 후속 구현 필요. |
| A5 | 이력 보완과 static Hard-LMM을 모두 제거 | B·A4·Full과 상호작용을 식별하는 조건. persistent memory 유지. 시너지 주장 때 필수. |
| A6 | 직전 관측이 있으면 여덟 분기를 모두 활성화 | 현재의 이력 길이별 활성 규칙이 단순한 잔차 세기 변화로 작용하는지 확인. 분모 8과 나머지 구조 유지. 활성 규칙의 효과를 주장할 때 필요. |

2×2 손실을 \(L_{00}\)(둘 다 없음), \(L_{10}\)(static 메모리만, B), \(L_{01}\)(보완만, A4), \(L_{11}\)(둘 다, Full)이라 하면, 보완 효과의 상호작용은

\[
(L_{10}-L_{11})-(L_{00}-L_{01})
\]

로 평가할 수 있다. 손실이 작을수록 좋을 때 양수는 메모리가 있을 때 보완 효과가 더 큰 방향이다. 같은 표본·seed에서 계산하고 불확실성을 함께 보고한다. 비선형 집계인 RMSE만의 차이로 강한 기전 해석을 하기보다, 표본별 제곱오차에서 시작한다. 이는 향후 분석 정의이며 현재 상호작용이 관측됐다는 뜻은 아니다.

## 5. 최신 TPP와 수량 예측 비교군을 선정한다 — 완료

선정은 **논문에서 답해야 할 질문에 대한 우선순위**다. 설치·재현·GPU 실행 적합성이 확인됐다는 의미는 아니다. “강한 비교 모델”은 원 논문의 결과와 과제 적합성에 근거한 후보이며, 이 데이터에서 강하다는 것은 새 실험으로 확인해야 한다.

| 우선순위·모델 | 이번 단계의 결정 | 비교 방식과 남은 확인 |
| --- | --- | --- |
| **핵심: S2P2 (NeurIPS 2025)** | 최근 TPP의 연속 시간 인코더 비교로 선정. | 과거 수량 입력을 추가하고 현재 공통 head/loss로 비교하는 `S2P2-matched`를 계획한다. 원래 intensity/likelihood 결과의 재현이라고 부르지 않는다. 공식 코드의 마지막 관측 사건 처리 후 상태를 사용하며, 다음 실제 시각을 알고 진화시킨 상태를 수량 예측에 사용하면 안 된다. [논문](https://arxiv.org/abs/2412.19634), [저자 저장소](https://github.com/UCIDataLab/state_space_point_process) |

현재 RMTPP·THP·NHP·SAHP 결과는 **현재 공통 head 프로토콜의 기존 비교 결과**로 보존한다. 새 입력·선택·튜닝 규칙이 달라지면 기존 결과와 공정하게 직접 비교할 수 있는지를 먼저 검토한다. 지금 재실행을 결정한 것은 아니다.

- **TimeMixer++(ICLR 2025):** 관련 연구에는 포함한다. 논문은 TimeMixer 저장소를 연결하지만 이번 검토로 ++ 전용 실행 경로를 확인하지 못했다. 구현 미확인을 “코드가 없다”로 단정하지 않는다. 설치 확인 없이 TimeMixer를 ++라고 표기하지 않는다. [논문](https://arxiv.org/abs/2410.16032)

- **PatchTST(ICLR 2023), DLinear(AAAI 2023):** 각각 추가 수량 비교와 낮은 복잡도 비교의 예비 후보다. 우선 TimeMixer와 단순 예측으로 역할을 충족시킨다. 예비 후보로 바꾸는 이유는 구현·과제 적합성 또는 사전 예산이어야 하며, 불리한 validation 결과를 보고 교체하지 않는다. [PatchTST](https://arxiv.org/abs/2211.14730), [DLinear](https://arxiv.org/abs/2205.13504)

## 6. 공정한 검증에서 빠지면 안 되는 질문을 고정한다 — 완료

**관측 가능한 정보가 같은가?**
- 수량 예측은 관측 이력만으로 다음 사건 수량을 추정해야 한다. 미래 실제 사건 시각을 조건으로 제공하는 예측은 별도의 쉬운 문제다.
- FlexTPP처럼 속성을 순서대로 생성하는 모델은 다음 시각을 먼저 예측·주변화한 후 수량을 예측해야 한다. likelihood 계산을 위한 teacher forcing과 실제 예측 경로를 구분한다. 미래 시각을 이미 안다는 조건부 수량 점수를 본 과제의 점수로 사용하지 않는다.
- 현재 mark-free 범위를 유지한다면 외부 모델의 필수 type을 상수로 처리하는 등 정보가 늘지 않는 적응을 명시한다. 수량을 임의 범주로 나누어 정답 type을 제공하지 않는다.
- TimeMixer의 시간 축 mixing은 **주어진 관측 prefix 안에서** 수행한다. 완성된 미래 포함 sequence를 넣고 모든 위치의 예측을 계산하면 누출될 수 있다.

**무엇을 동일하게 비교하고 무엇을 원래 방식으로 남기는가?**
- 공통 head 비교는 인코더 차이를 본다. 입력, head, loss, checkpoint 선택과 튜닝 예산을 맞춘다. S2P2-matched는 이 범주다.
- 외부 방식 비교는 모델의 원래 head·목적함수 장점을 허용한다. 동일한 관측 정보·예측 대상·검증 표본·검색 예산에서 경쟁력을 본다. head가 달라진 비교를 이력 인코더만의 인과 효과로 해석하지 않는다.
- native head라도 보고하는 주 수량 지표는 같은 raw RMSE/MAE여야 한다. 분포 예측의 평균을 계산할 때 `exp(E[log q])`를 `E[q]`라고 잘못 사용하지 않는다. 샘플링으로 평균을 구한다면 샘플 수·오차·추론 비용을 함께 고정한다.
- 시간 NLL은 현재 기록 간격의 round/clamp 및 Instacart 30 top-code 관측 규칙과 동일한 **확률 질량**으로 변환 가능할 때 비교한다. 연속 밀도 NLL과 그대로 대조하지 않는다. 수량 log-MSE와 외부 joint NLL도 같은 지표가 아니다.
- 수량 전용 TimeMixer에는 시간 NLL을 `해당 없음`으로 표기한다. 0으로 채우거나 시간까지 우수하다고 해석하지 않는다.

**어떤 데이터에서 유리한지를 실제로 설명할 수 있는가?**
- 세 데이터 모두 유지하고 각 seed의 결과를 공개한다. Taxi만 남겨 전체 데이터의 우위로 바꾸지 않는다.
- 과거 수량 수준·최근 변화량·간격·관측 길이와 효과의 연관을 살핀다. 구간 경계는 train 통계 또는 사전 규칙으로 고정하고 작은 구간의 표본수를 명시한다.
- 실제 다음 수량으로 나눈 tail 구간은 사후 오류 진단에 사용할 수 있지만, 예측 시 사용하는 조건이나 모델 선택 규칙으로 사용하면 안 된다.
- 이력 길이별 분기 활성 수와 고정 분모 8 때문에 변화하는 잔차 세기가 설명의 대안이다. 수준·변화 성분의 효과와 이를 분리해야 한다.
- 같은 계열의 사건을 독립 표본처럼 취급하지 않는다. 계열/시간 블록 의존성을 고려한 paired 분석을 설계한다. 세 seed의 표준편차만으로 유의성을 선언하지 않는다.
- 시간 손실 악화를 곧바로 gradient conflict의 증거로 부르지 않는다. 그 원인을 주장하려면 별도 진단이 필요하다.

**효율성의 범위는 어디까지인가?**
- 보완 모듈의 길이 방향 선형 연산량과 전체 attention 모델의 복잡도를 구분한다. 현재 전체 모델이 선형이라고 주장하지 않는다.
- 동일 epoch 수와 조기 종료를 포함한 전체 학습비용을 함께 본다. 모델별 유리한 시점만 골라 비교하지 않는다.
- 기존 학습시간은 실제 관측 증거로 유지하고, 정확한 처리량·지연 비교는 후속의 동일 5080 조건에서 검증한다. 이번에 서버를 점유하거나 측정한 것은 아니다.

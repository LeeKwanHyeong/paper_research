# MLP16의 후기 관측 경로를 검증할 준비

**현재 실험을 보존한다 — 현재 기준선 / 진행 중**

- 대상은 paper_research의 `codex/contextual-retrieval-pilot-20261007` 브랜치다.
- Cap·MLP16·시간 가중치0의 수량 손실18개와 뒤에 연결된 원시간 입력27개는 그대로 둔다. 이번 준비에서 원격 조회·배포·추론·학습·회수·후속 작업 등록을 하지 않는다.
- 기존 CNN 모델·checkpoint·원본 결과·실패 기록은 변경·재학습·재평가하지 않는다. 현재 source952와 후속 source955의 모든 기존 파일 SHA를 준비 전후 확인한다.

**정보를 다시 제공하는 위치와 두 구조를 고정한다 — 완료**

공통 모델은 현재 이력 MLP16이다. 첫 attention 이후 현재·직전 문맥 표현을 읽는 기존 MLP와 두 attention block을 모두 유지한다. 각 관측 위치에서 기존 시간·수량 입력을 64차원으로 선형 투영한 출력 e0를 사용한다. e0는 위치 임베딩 전이며 다음 이벤트의 정답이나 미래 시간 간격을 사용하지 않는다.

| 구조 | LMM에 전달하는 표현 | 추가 가중치 |
|---|---|---:|
| 현재 MLP16 참조 | h2 | 0 |
| 후기 관측 경로 후보 | h2 + P(e0) | 1,024 |
| 후기 문맥 경로 대조 | h2 + P(h2) | 1,024 |

P는 bias 없는 64→8→64 GELU다. 두 팔의 출력 투영은0으로 초기화하고 초기 공통 모델 tensor와 RNG를 보존한다. 부모 MLP16의 공통 head·메모리·이력 분기나 입력 변환은 바꾸지 않는다. 초기에는 두 팔 모두 기존 MLP16과 같은 예측을 내야 한다. 유효 관측 mask 및 withheld 경계를 유지한다.

이 후보는 10월18일 상한 적용 전 분석에서 남긴 미실행 MLP4 설계를 현재 요청의 MLP16으로 구체화한 것이다. 원관측 소실의 원인이 확인된 것은 아니며, 기존 residual 연결도 입력 정보를 전달한다. 명목 용량을 맞춰도 입력 rank·함수 공간·최적화 경로가 같아지는 것은 아니다. LMM 앞 상태가 바뀌면 검색되는 prototype도 바뀔 수 있으므로 메모리와 독립적인 효과라고 주장하지 않는다.

**새 파일에서 구현하고 합성 입력으로 검증한다 — 완료 / 독립 파일 병렬**

- 모델 구현과 테스트는 별도 새 파일에서 병렬로 준비한다. 공통 명세·통합 검토·증적 확정은 직렬로 한다.
- 검증 대상은 초기 동등성, 동일 용량, 두 정보 출처의 수식 일치, 미래 입력 차단, padding·withheld 처리, gradient 연결, 저장·복원, 두 팔 checkpoint 오인 방지다.
- 합성 CPU 검증은 실제 학습이나 native GPU 검증을 대신하지 않는다. 기존 데이터의 새 추론은 하지 않는다.
- 실제 단위 검사15개와 두 후보×세 수량 목적의 합성 통합 조건6개가 통과했다. 통합 조건은 각각 가짜 optimizer step2회이며 실제 데이터의 fit이 아니다. 독립 구현 읽기검토에서도 중간 이상 발견은 없었다.
- 첫 단위 검사에서 시간 NLL의 입력 shape 및 초기 수량 head의 zero gradient를 잘못 가정한 fixture 오류가 있었다. 테스트만 고친 뒤 통과했고 모델을 그 오류에 맞춰 바꾸지 않았다. 최초 출력 전사본은 원문 stdout/stderr 분리 캡처가 아님을 표시해 보존했으며 root 재실행의 stdout/stderr·실제 종료코드는 별도로 보존했다.

**입력·손실 조건을 확정하고 실행 여부를 결정한다 — 외부 작업 대기 / 새 학습 결정 전**

- 진행 중인 손실 비교와 승인된 원시간27 비교의 최종 결과를 기다린다. 데이터셋별로 다른 손실이나 입력을 골라 조합하지 않는다.
- 현재 모델 준비는 부모의 log1p 시간·수량 입력을 상속한다. 원시간을 선택할 경우 두 팔·참조에 동일하게 적용하는 별도 실행 계약이 필요하며 현재 후속 실험을 수정하지 않는다.
- 사용자가 준비 결과를 보고 새 학습을 결정한 뒤에만 별도 실행 경로·host 배정·고정 예산·native 검증을 준비한다. 예상 후보 수는 두 팔×세 데이터셋×3seed=18개이며 이번 문서는 시작 승인이 아니다.
- 기존 MLP16 저장 참조는 입력·손실·시간 가중치·seed·대상·학습/선택 조건이 실제로 같은 경우에만 재사용한다. 맞지 않는 참조를 동등 조건이라고 부르지 않는다. CNN 기준선 학습은 추가하지 않는다.

**조건을 고정한 Validation으로 후보를 판정한다 — 실행 승인 후 다음 작업**

- 전체 Validation 실수량 RMSE의 최초 strict finite 최소 epoch를 고정하며 동률이면 첫 epoch를 쓴다. MAE는 같은 checkpoint에서 보고한다.
- 후보가 참조와 동일 용량 대조보다 세 데이터에서 RMSE·MAE 평균 모두 낮아야 공통 후보로 남긴다. 모든 seed 예외·평균±표본SD(ddof1)·상한 도달 집단·시간 진단값을 보존한다.
- 두 새 팔이 비슷하게 좋아지면 e0 정보 출처의 추가 이득을 입증하지 못한 결과로 판정한다. 일부 데이터/한 지표만 개선돼도 공통 성공으로 합치지 않는다. 실패한 뒤 rank·gate·손실을 계속 바꾸는 자동 탐색은 연결하지 않는다.
- Test·외부 모델 우월성·수량/시간 공동 TPP 개선은 이번 준비와 Validation 판정의 범위에 포함하지 않는다.

**준비 결과를 기록한다 — 완료 / 로컬 준비 범위**

- 로컬 준비 증적에는 실제 검사 수·종료 코드·source/명세 SHA·한계·실제 학습0·native GPU 미검증을 구분한다.
- 이번 작업의 새 모델·테스트·문서만 paper_research의 위 브랜치에서 별도 커밋한다. Push·원격 배포는 하지 않는다.
